## Deviations from plan

### Auto-fixed / adjusted

**1. [Rule 2 — missing critical functionality] The weak-spots tab had TWO
"not written yet" sites, and the plan named one.**

- **Found during:** Task 2.
- **Issue:** the plan says to "replace the not-written line with a link". There
  is the inline `nothingYet` paragraph *and* a full empty-state card that reads
  *"We haven't written practice for this topic yet."* The empty-state card is the
  one the learner actually hits in the most likely case — the volume tier being
  her **only** weak topic — and fixing only the inline line would have left the
  false statement exactly where it does the most damage.
- **Fix:** `CORE_VOCAB_TOPIC` is excluded from `unpractisable`, a
  `volumeElsewhere` link element renders in both branches, and the empty-state
  card is now conditional on `unpractisable.length > 0`. A comment records that
  exactly one of the two always renders, so there is no path to a blank tab.
- **Commit:** `aa1002c`.

**2. [Rule 3 — blocking] The route weight is not in the build output.**
Measured from the route's client-reference manifest instead; method documented
above. No code change.

### Judgement calls the plan left open

- **`CORE_VOCAB_TITLE` had no specified home.** Placed beside `CORE_VOCAB_TOPIC`
  and defined as equal to it, with the reason written down.
- **`coreVocabBands()` returns `RecallItem[][]`**, not `CoreVocabCard[][]`. The
  plan said "`recallBatches(cards, …)`"; the surface needs ids for its own
  met/due counts and words for the band range, and one shape means the band list
  and the deck it launches cannot disagree.
- **`CORE_VOCAB_BAND_SIZE` is 50, larger than `RECALL_BATCH_CEILING` (16).** A
  band is a unit of the deck she chooses from a list, not a sitting she is walked
  through; `RecallDeck` applies the ceiling again inside a band, so 50 never
  means fifty cards without a rest point.
- **`CORE_VOCAB_LEVEL` is `A1`** and is deliberately **not rendered** on the
  surface — it is stored as attempt metadata only, so it never becomes an
  un-gated claim.

## Things the plan did not predict — read these before plan 02

1. **Plan 02 §D says "the bank never spells the id format by hand **and calls
   `coreVocabItemId(`**".** Those two clauses contradict each other, and they
   contradict plan 01's "nothing outside this module spells the format". The bank
   stores the **slug** in `id` and does **not** import `core-vocab-items.ts` —
   which is what keeps the two files acyclic and is also what plan 02 task 1's own
   digest assumes (it computes `coreVocabItemId(card.id)` itself, so `card.id`
   must be the slug). **Plan 02 must assert that the bank never spells `vocab:`,
   and must not assert that the bank calls `coreVocabItemId`** — that assertion
   would fail against a correct bank.
2. **"the 280 scenario cards" is wrong: `scenario-vocabulary.ts` holds 352
   terms.** CONTEXT and plan 02 §A.4 both say 280. The duplicate check must be
   built from the bank's actual contents; if plan 02 writes a literal it will be a
   tripwire on the wrong number.
3. **Plan 01's action text still contains the stale sentence "The list itself is
   public and citable"**, which the corrected precondition supersedes — it is
   CC BY-SA 4.0 with attribution *and* share-alike obligations. The precondition
   was followed, not the action text.
4. **The `:` collision surface is wider than L1's claim, and now provably so.**
   No `VOCAB_DECKS` deck id is `vocab` (checked: `daily, connectors, phrasal,
   work, idioms, food, travel, feelings, people, phrasal2, money, opinion,
   collocations, phrasalAdv, nuance, idioms2, formal`), so `vocab:` is safe today
   — but `daily:0` already exists, so the property must be asserted as plan 02 §C
   says, not inherited from L1's narrower statement.
5. **Next 16.2.9 + Turbopack prints no per-route bundle sizes.** Any future plan
   asking for a route weight "from the build output" needs the manifest method
   above.
