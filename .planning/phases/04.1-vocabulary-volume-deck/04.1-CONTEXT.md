<locked_decisions>
## Locked decisions — do not re-litigate these

### L1. Id space: `vocab:<slug>`, a NEW key space

**Decided by the user on 2026-08-04, after the originally-designed shape was proved broken.**

DESIGN §1 proposed `core/vocab#word#<slug>` as a pseudo-scenario, on the belief that it would
flow through every existing mechanism unchanged. **It does not, and the reason is not a harness
assertion that could be scoped — it is a runtime function.** `parseScenarioItemId`
(`src/lib/review-items.ts:132-142`) ends with:

```ts
if (!getScenario(worldSlug, scenarioSlug)) return undefined;
```

Measured live before any card was written:

```
parseScenarioItemId('core/vocab#word#house')   -> undefined
parseScenarioItemId('core/vocab#vocab#house')  -> undefined
resolveReviewItem('core/vocab#vocab#house')    -> undefined
```

A `core/vocab` card would be **stored, merged and scheduled correctly and never rendered** — the
exact D-05 failure `review-items.ts` was written to make impossible, reproduced 500 times in
permanent keys.

**So the volume deck gets its own key space:**

- Its **own** compose/parse pair, in its own module or its own clearly-separated section.
- Its **own branch** in `resolveReviewItem`.
- Its **own source** in `reviewableIds()` — this bank IS scored, so unlike writing/reading/
  speaking it **must** be listed there. Check the renderer calls `recordAttempt` before wiring it,
  per `AGENTS.md`'s conditional rule.
- **`parseScenarioItemId` is NOT touched.** `verify-scenario-content.mts:389-396` — the four
  assertions that an unknown key parses to nothing — stay **exactly as written**. They are
  deliberate tripwires; scoping or deleting them to admit `core/vocab` is weakening a gate to fit
  content, which this project has refused since Phase 2.
- The **`:` is the collision property**, the way `/` was for the scenario space in Phase 3.

  **CORRECTED 2026-08-04 — this claim was narrower than the collision surface, and the narrow
  version is the one nobody should rely on.** It originally read "no scenario id and none of the
  39 global grammar ids carries one." True, and beside the point: `src/lib/content/vocabulary.ts`
  already builds the deck browser's card ids as `` `${deckId}:${i}` ``, so **`daily:0` exists
  today**. `vocab:` is safe only because no `VOCAB_DECKS` id is `vocab` — verified against
  `daily, connectors, phrasal, work, idioms, food, travel, feelings, people, phrasal2, money,
  opinion, collocations, phrasalAdv, nuance, idioms2, formal`. **Assert against all four key
  spaces, and assert that no deck is named `vocab`.** Do not trust either.

### L2. Bank: `src/lib/content/core-vocabulary.ts`, and the missing field IS the design

```ts
CoreVocabCard = { id, word, es, example }   // NO tip field
```

Alias-free, React-free, explicit `.ts` extensions — like every other bank, so the harness loads it
standalone under `node --experimental-strip-types`.

**The absent `tip` is load-bearing.** This project's own rule is that an optional field is one an
author forgets. The volume tier's lower bar is therefore expressed by the type having **nowhere to
put a register note**, not by a convention someone has to remember. A card that genuinely needs one
belongs in a scenario bank instead.

### L3. Volume: 500, and stop

Confirmed by the user on 2026-08-04 *after* the corrected payload measurement below. A second batch
is a **fresh decision with the ceiling re-measured**, not an assumed continuation.

### L4. Two tiers, declared — never blended

The same move this project has made with derived coverage since Phase 2.1: **never blend two
quality levels and present them as one.** The UI must let a learner tell a volume card from a
scenario card without being told. Mixing them silently is the overclaim every phase since 2.1 has
been built to prevent.

<the_ceiling_is_real>
## Payload — measured live today, and it caps the ambition

The design table extrapolated from **252 B/id**. The harness was run and the real figure is
higher:

```
payload:    205,174 B saturated over 752 scheduled id(s) — 19.6% of the 1,048,576 B cap
```

That is **272.8 B per id**, not 252.

| Added | Total | % of cap | Under the 40 % rule? |
|---|---|---|---|
| +500 | ~341,600 B | **~32.6 %** | **yes**, ~7 points of margin |
| +1,000 | ~478,000 B | ~45.6 % | **no** |
| +2,000 | ~750,800 B | ~71.6 % | no |

**It does not fail gracefully.** The route answers **413** above the cap and `sync-queue`
classifies 413 as *permanent* and **drops the slot**. Crossing the cap does not degrade — it
**silently stops syncing the learner's progress**. So the growth path must be gated with headroom,
not discovered.

The real ceiling is nearer **3,090** cards than the 3,346 the design estimated, and the
8,000–11,000-card fluency deck is **not reachable in the JSON-column design at all** — that needs
DATA-01 (normalised progress schema), which sits in the v2 backlog.

**A plan must re-measure from the harness after the batch and print the figure.** Extrapolation is
what produced the wrong 252.
</the_ceiling_is_real>

<quality_floor>
## The quality floor, as assertions

At volume, prose quality degrades where the existing corpus scan cannot see it: it detects
**repeated words**, not flat translations or dull examples. So the floor is mechanical:

1. Every field non-empty.
2. The `es` gloss is **not** the English word.
3. The `example` **contains the word** (inflected forms allowed) and runs **≥ 6 words**.
4. **No duplicate word** within the deck, and **none against the 352 scenario vocabulary terms**.
5. **Provenance:** every word is on the NGSL, asserted against a **committed copy** of the list.
6. **Frame diversity.** Signature each example by its opening shape (first two words lowercased,
   or a part-of-speech-ish approximation) and assert **no signature exceeds ~5 % of the deck**.

Number 6 is the one that addresses the actual risk. Five hundred examples that all begin
*"I have a…"* pass checks 1–5 perfectly and are exactly what "flat" means. It is the volume tier's
automated equivalent of the consecutive read that caught repeated syntactic frames in Phases 3 and
4 — automated **because at 500 nobody will read them all**.
</quality_floor>

<constraints>
## Constraints this phase inherits

- **An SRS id is a one-way door.** 500 cards are 500 permanent keys. Insert freely; **never**
  renumber or rename. A replacement is always *retire the old id, add a new one*.
- **`verify-id-stability.mts` hashes the WHOLE authored record.** Rewriting an `example` under a
  live id is a re-point and fails. So: regenerate the fixture **once, after content is final**, in
  the **same commit** as the content. `--update` deliberately refuses to launder a changed hash and
  cannot tell an uncommitted rewrite from a real re-point (04-07 tripped exactly this).
- **A gate that has never failed is a gate nobody has tested.** Aim a mutation at every assertion
  added, require it to be CAUGHT **on its own label**, and keep controls that must survive. A
  non-zero exit from a syntax error is not a catch.
- **A mutation sweep can poison a `.next` build that outlives it** (03-08). Run sweeps in a
  worktree or scratch copy; rebuild from the committed tree before claiming anything from a build.
- **The beta user has a dated CELPIP exam.** Nothing here may destabilise `/celpip`.
- **Licensing — corrected 2026-08-04, this bullet was wrong when first written.** The NGSL is not
  merely "public and citable": it is **CC BY-SA 4.0** (Browne, Culligan & Phillips), which carries
  attribution **and** share-alike obligations. The user's decision is to commit the fixture with
  full attribution — authors, official URL, retrieval date, version 1.2 (April 2023), licence name
  and text. Share-alike attaches to that file; the cards are original prose, not an adaptation.
  The list answers *which words* and contributes **no sentence** to the app. That line has held
  since Phase 1 and is not relaxed by volume pressure.
- **The official domain is `newgeneralservicelist.com`.** `newgeneralservicelist.org` — cited by
  Wikipedia and by this project's own earlier notes — **has been taken over and now serves
  online-casino content.** Do not cite it anywhere.
</constraints>

### L5. Its own deck surface, its own queue — NOT the shared `/review`

**Decided by the user on 2026-08-04**, asked before planning because it shapes the plans.

The volume deck gets an **Anki-shaped surface**: "study *this deck* now." Its cards do **not**
enter `/review`'s shared due/mistakes/weak-spots queue.

Two reasons, both concrete:

1. `/review` today holds **752** scenario items earned across Phases 3 and 4 — the app's
   highest-quality content. Adding 500 lower-tier cards to the same queue makes `/review` roughly
   40 % loose NGSL vocabulary within days and **buries** that work.
2. The request document already named these as **different products on the same engine**. This
   makes that explicit instead of collapsing them.

**Planning consequences, and they are load-bearing:**

- The Leitner engine, `recordAttempt` and the `srs` store are **shared** — this is a queue
  decision, not an engine fork. Volume ids still live in Postgres `srs` and still count against
  the payload figures above.
- **`reviewableIds()` is the shared-queue enumerator.** L1 said this bank "must" be listed there;
  **L5 supersedes that** — listing volume ids there is what would put them in the shared count.
  Whatever enumerator the new surface needs is its own. Get this wrong in the omit direction and
  the cards are invisible; wrong in the add direction and they flood `/review`. Assert whichever
  way the plan lands, per `AGENTS.md`'s symmetric-cost rule.
- `Dashboard` and `ReviewHub` build "Due today" by filtering the due set through `reviewableIds()`.
  Their counts must be **unchanged** by this phase, and that is assertable.
- **No opt-in toggle.** A mix-into-`/review` switch was offered and declined: a preference is one
  more thing to persist, test and forget, and this project's own rule is that an optional field is
  a field someone forgets.
