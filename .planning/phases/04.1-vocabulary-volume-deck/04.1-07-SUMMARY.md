### Counting discipline

```
declared        52
executed        52
mutations       46, CAUGHT on their own label: 46
controls         6, SURVIVED: 6
```

Every verdict carries two things the count alone would not:

- **a landing proof** — the driver compares the mutated text to the original and
  reports `SETUP-ERROR` if the find string matched nothing, so a mutation that
  never landed cannot be scored;
- **a parse check** — through TypeScript's own parser (`parseDiagnostics`), or
  `JSON.parse` for the fixture, because **a non-zero exit from a syntax error is
  not a catch**.

04-01's two harness defects were read first and neither is present: the child's
status comes from `spawnSync`'s own `status` field with nothing piped, and nothing
is passed through `process.argv`. Plan 02's CRLF lesson is applied — matching is
done on an LF-normalised copy and the **original bytes** are restored verbatim.

### Three defective mutations, diagnosed as defective before any assertion was blamed

This is 04-01's ordering, and it is the discipline that separates a sweep from a
report of one.

1. **M05, first attempt** — added an unused *parameter* to `card()`. The assertion
   reads `Object.keys(item)` off the **built record**, and a parameter nothing
   stores adds no key. The mutation was wrong, not the assertion; aimed at the
   returned object it is caught on its own label with one failure.
2. **R02, first attempt** — `"[^"]*"` stopped at the first **escaped** quote inside
   the retirement's own reason (which quotes `"color / tono"`), leaving invalid
   JSON. **The parse check caught it as `SETUP-ERROR` rather than letting a broken
   file be scored as a catch**, which is exactly what that check is for.
3. **N07 and N08 — and this one was the ASSERTION, not the mutation.** See below.

### The assertion that survived its own mutation

**Two mutations wrote "500" into the copy — the precise overclaim the assertion
exists to catch — and the gate stayed green.** Both times. Investigated in the
order the rules require, and the mutation was fine; the check was not, in two
independent ways:

- stripping `{…}` innermost-first eventually reaches the **component function's own
  body braces** and eats the whole thing, leaving no text to scan;
- text bounded by `>` and `<` captures `dueCount > 0 && (` and `pct = … * 100` as
  prose, so code read as copy while copy read as nothing.

Both failures are **silent, and both make the assertion vacuous rather than loud**
— which is the worst possible direction for a check whose whole job is to catch a
number in a sentence. An approximation of "what a learner reads" cannot be trusted;
`JsxText` is a **node kind**, so the check now asks TypeScript for it. One
`createRequire("typescript")` — already a devDependency this repo runs `tsc` from
on every plan, so nothing is installed and **11 + 11 does not move**.

Committed as `912cb02` with the finding in the message. This is the single most
useful thing the sweep did, and it is the argument for the rule that produced it.

### Finding 2 — a front answerable by a different English word

The **taken-front** strategy 04.1-06 used fifteen times (re-gloss rather than skip,
so a high-frequency word still gets a card) pushes a gloss off its headword's
central sense. `es` is the **front** — she sees it first and produces the English
from it — so the cost is a card whose most natural answer is a *different* word.

| card | front | a learner most naturally answers |
|---|---|---|
| `standard` | "habitual" | *usual* |
| `complete` | "rellenar" | *fill in* |
| `evidence` | "indicios" | *clues* |
| `response` | "reacción" | *reaction* |
| `relate` | "vincular" | *link* |

**`standard` is the sharpest, and it is worse than the others**: the example is
*"I chose standard delivery and waited nine days"*, which teaches the
default-option sense — and that is **not** "habitual". Gloss and example teach
different senses, the exact defect 04.1-05 fixed on `agree` when it caught it.

**Measured mitigation rather than an assumed one:** none of *fill*, *link*, *react*,
*clue*, *usual* or *normal* is a card, so **no front has two right answers inside
the deck**. That materially softens all five — they are cards teaching a secondary
sense under a front pointing elsewhere, not questions with two keys. WINDOWS 72.

### Finding 3 — three examples lean on a word a B1 learner will not know

The one thing the ≥ 6-word floor cannot see: the *other* words.

- `affect` — *"Damp affects the plaster on that north wall."* needs **both** *damp*
  as a noun and *plaster*.
- `demand` — *"Demand for allotments doubled after the lockdown."* turns on
  **allotments**, a low-frequency British word carrying the sense.
- `fund` — *"He ran through the funds in under a year."* hides the meaning in the
  phrasal verb *ran through*.

And a **class** worth naming above any single card: **a two-sense gloss with a
one-sense example**. `time` "tiempo / vez", `back` "espalda / de vuelta", `way`
"manera / camino" — the front offers two Spanish words and the example shows only
the first. Legal under every assertion, and still half a card. WINDOWS 73.

### What the sitting read well

Band 1 is strong and holds up read end to end: fifty concrete sentences, no two
alike, no repeated frame, no card that merely contains its word. *"Grandma hurt her
back lifting those heavy boxes"*, *"It'll take about twenty minutes by bus"*,

than mentioning it, which is question 2 answered in the affirmative fifty times.
The parenthetical device is used well and consistently where a bare gloss would

## Things the plan or the gates got wrong

1. **The plan's own independent-enumeration check would have failed as written.**
   Its `<automated>` block invokes `node --experimental-strip-types -e` with a
   multi-line inline program; under `-e` the relative specifiers resolve against the
   cwd rather than a module URL, and the one-liner is unquotable on this platform.
   Written to a scratch file it works exactly as intended, which is how it was run.
2. **The plan's `curriculum.ts` / `scenario-coverage.ts` diff check uses
   `git merge-base HEAD main`, and the phase was executed ON `main`.** The
   merge-base of `main` with itself is `HEAD`, so the check compares HEAD to HEAD
   and is **vacuously green on any change**. It was run against the phase's first
   code commit instead (`ff1f6ca^..HEAD`), which is the range the criterion means.
   A check that cannot fail is worth nothing, and this one could not.
3. **`verify-scenario-content.mts:389-396` is now 401-416 and the citation is still
   in REQUIREMENTS and in this phase's own documents.** 04.1-02 recorded the shift;
   the requirement text was never updated. **Cite the four parse tripwires by their
   text** — *"a scenario key the curriculum does not have parses to nothing"* — and
   the note is now in the requirement itself.
4. **The idempotence-check ordering defect ran the whole phase and was never
   fixed.** Plans 02, 03, 04, 05 and 06 each recorded it, twice with an
   `<ordering_correction>` block that fixed the prose and left the `<verify>` block
   wrong. **Five recordings and no fix is a process finding, not a plan finding**,
   and it is the same shape as the removed-line defects this gate did close: a
   correction that does not edit the thing it corrects will be followed by whoever
   reads the block and missed by whoever reads the checks.
5. **The plan asks for "a mutation per assertion this phase added" and the phase
   added 7,337.** They are not 7,337 distinct assertions — they are ~15 assertion
   *kinds* multiplied by 500 cards. The sweep aims at kinds, which is the only
   reading under which the instruction is executable, and the table names each.
