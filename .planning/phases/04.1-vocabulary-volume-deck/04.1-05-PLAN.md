<objective>
The third volume batch: 120 cards, taking the deck from 260 to **380**.

The batch where the deck stops being easy. The top of a frequency list is concrete and picturable —
*house*, *water*, *money* — and by this depth the headwords are abstract, functional and polysemous:
words like *however*, *particular*, *available*, *consider*, *rather*. Three things get harder at once
and all three are gated:

- **The example gets harder.** A concrete noun writes its own sentence; an abstract adverb does not.
  This is where "one natural sentence somebody would say" degrades into a definition wearing a
  sentence's clothes.
- **The gloss gets harder.** Abstract words have no clean one-word Spanish equivalent, and the
  temptation is a dictionary string of near-synonyms. `es` is the **front** of a recall card — a front
  that lists four options is a card the learner cannot answer.
- **The skip register gets tempting.** It exists for words a flashcard cannot teach, not for words
  that are tiring to write. **"Hard to example" is not one of its reasons.** The only admissible
  difficulty-shaped reason is the narrow one: the headword's base form genuinely cannot appear in its
  own example. If the register grows unusually in this batch, say so in the summary and say why for
  each entry.

**If execution stops right after this plan**, the learner has 380 core words counted honestly, every
gate green, every id recorded.

Purpose: the third real volume, through the part of the list where quality is actually decided.
Output: 120 cards, a regenerated fixture, a payload figure and an updated histogram.
</objective>

## Run the near-duplicate scan BEFORE regenerating the fixture

As written, Task 1's verify runs `verify-id-stability.mts --update` and Task 2 then scans for
near-duplicates and **rewrites cards**. That order is wrong and it contradicts this phase's own
rule: content is not final until the scan has run, so regenerating in Task 1 either bakes in a
hash you are about to invalidate or invites a second `--update` to launder it.

**"Twice is fine because it is uncommitted" is exactly the habit 04-07 came from.** Plan 03 hit
this, inverted the order, and regenerated once; do the same here.

**Correct order:** author the cards → run the near-duplicate scan and make every rewrite → *then*
`--update`, **once** → commit content and fixture together, atomically. Task 1's `--update` verify
becomes an idempotence check that runs after the scan, which is the only point at which it can
pass.
</ordering_correction>

**The three things this batch has to get right, because the list has changed underneath it:**

1. **An example for an abstract word is a situation, not a definition.** "However" is not taught by
   *"However is used to contrast two ideas"* — that is a grammar note with no register, in a bank whose
   type deliberately has no room for one. It is taught by a sentence in which the contrast is doing
   work: someone changing their mind, someone qualifying a promise. Write the situation.
2. **One gloss, not a list.** Where a word has several senses, pick the sense the frequency list is
   counting — the dominant one — and gloss that. A front reading *"sin embargo / no obstante / aunque /
   pero"* is four cards pretending to be one, and the learner cannot answer it. If two senses are both
   genuinely dominant and genuinely different, the honest move is one card for the sense you teach and
   a note in the summary that the other sense is untaught. **Do not invent a second card for the same
   headword** — no duplicate word is an assertion, and it is there for a reason.
3. **Polysemy across tiers.** By this depth some headwords overlap with words a scenario card already
   teaches in a specific register sense. That is a declared skip with the "already taught by a scenario
   card" reason — the assertion will force the issue anyway, and declaring it deliberately is cheaper
   than discovering it.

Read plan 04's histogram first; the openings it spent are unavailable habits. Abstract words pull hard
towards a single frame — *"It's important to…"*, *"You should…"* — so the ceiling matters more in this
batch than in either before it. Run the harness at the midpoint.

**Regenerate the fixture in THIS commit**, once, after the content is final: additions only, nothing
