## Spacing Scale

Declared values (must be multiples of 4), matching what's already in use across `Dashboard.tsx` / `WorldCard.tsx` / `WritingDesk.tsx`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inline padding |
| sm | 8px | Compact spacing (word-counter row, checklist item gaps) |
| md | 16px | Default element spacing (card internal stacking, `mt-4`) |
| lg | 24px | Section padding (card `p-6`, `gap-5`≈20 rounds to this band) |
| xl | 32px | Layout gaps between major page blocks |
| 2xl | 48px | Major section breaks (landing hero → task grid) |
| 3xl | 64px | Page-level top/bottom spacing |

Exceptions: icon-only controls (timer pause/resume button, mobile) use a **44px** minimum touch target regardless of visual icon size, per standard mobile tap-target accessibility — this is the only allowed deviation from the 4px grid, applied via padding, not element size.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | 600 semibold | 1.3 |
| Body | 16px (`text-base`) | 400 regular | 1.5 |
| Heading | 18px (`text-lg`, `font-display`) | 600 semibold | 1.2 |
| Display | 28–30px (`text-3xl`, `font-display`) | 600 semibold | 1.1 |

Notes:
- **Body (16px)** is deliberately larger than the codebase's default `WritingDesk.tsx` precedent (14px `text-sm`) for two elements only: the **writing editor textarea** and the **prompt/scenario paragraph** — this is a 25-minute high-stakes writing task, so body-text comfort takes priority over matching the lighter-weight practice widget. All other UI text (badges, meta rows, checklist items, timestamps) uses the 12px Label size, consistent with `SkillPill`/`LevelBadge`.
- Only two weights exist in this contract: 400 (regular, body prose only) and 600 (semibold, everything else — headings, labels, buttons, badges). No 500/700 introduced.
- Countdown timer digits use the Display role (28–30px) for legibility at a glance, tabular/monospace numeral rendering (`tabular-nums`) to prevent digit-width jitter each second.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--paper)` (#faf4e9 light / #17130f dark) | Page background on `/celpip` and simulator route |
| Secondary (30%) | `var(--card)` (#fffdf8 / #201a14) and `var(--paper-deep)` (#f2e9d8 / #211b15) | Task cards, editor panel, results panels, rubric panel, sidebar/nav chrome |
| Accent (10%) | `var(--sky)` (#2f6f9e light / #5fa0d0 dark) | Reserved for the elements listed below only |
| Destructive/Warning | `var(--vermilion)` (#e0492a / #f0653f) | Reserved for the urgent-state elements listed below only |

Accent (`--sky`) reserved for:
- Primary CTA buttons ("Start Timed Attempt", "Start Practice", "Submit")
- The active/selected Task 1 vs Task 2 tab on `/celpip`
- Word-counter "in range" state (150–200 words) and its checkmark
- Checked rubric checklist items and their checkmarks
- Attempt-completed progress indicator on task cards (reuses `ProgressRing` with `color={accent}` per existing `WorldCard.tsx` pattern)

This follows the existing codebase convention where `writing` skill's assigned color is already `--sky` (`SKILL_META.writing.color`, and `WritingDesk.tsx`'s default `accent` prop) — CELPIP inherits it rather than introducing a new hue.

Destructive/Warning (`--vermilion`) reserved for:
- Countdown timer face once ≤2 minutes remain (urgency, not deletion)
- The timer-expired lock banner and its "time's up" state
- Word-counter over-range state (>200 words) — visual flag only, never blocks typing or submission

No delete/destroy action exists in this phase (see Copywriting Contract below), so `--vermilion` here signals **urgency**, not **destruction** — that distinction must hold in implementation (no trash icons, no "delete" language attached to this color in this phase).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Start Timed Attempt" (exam mode, on a task card / task detail before entering the simulator) |
| Empty state heading | "No attempts yet" |
| Empty state body | "Pick a task below and complete your first timed practice — your attempt history will show up here." |
| Error state | "We couldn't save your draft just now. Keep writing — we'll keep trying, but copy your text somewhere safe if you're about to close this tab." (autosave/localStorage write failure) |

## Visual Hierarchy (focal points)

Added 2026-07-23 per checker Dimension 2 recommendation. One primary visual anchor per key screen:

- **`/celpip` landing**: primary anchor is the Task 1 / Task 2 card grid — the page hero (what CELPIP is) stays compact so the cards sit above the fold; "coming soon" tabs are visually secondary (muted, no accent).
- **Simulator (`/celpip/writing/[taskId]`, writing state)**: primary anchor is the editor; the countdown timer is the strongest secondary element (fixed position, top of the writing column) so it's always visible without competing with the writing surface. Word counter is tertiary, attached to the editor's bottom edge.
- **Simulator (results state)**: primary anchor is the side-by-side comparison (user text | model answer); the rubric checklist follows directly below as the natural next action; attempt metrics are a compact tertiary strip.

## UI Considerations

Applicable state considerations resolved: 14 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | attempt-history-list (list-collection) | ✅ covered | Zero attempts renders the "No attempts yet" empty-state copy defined above (Copywriting Contract). |
| empty | writing-editor (form) | ✅ covered | Empty textarea shows placeholder "Write your answer here…", matching the existing `WritingDesk.tsx` pattern. |
| empty | task-library-cards (list-collection) | ✅ covered | Dismissed — task bank ships pre-seeded with ~8 Task 1 + ~8 Task 2 entries; never empty at runtime in this phase, no empty state needed. |
| empty | rubric-checklist (form) | ✅ covered | Dismissed — rubric items are static per-task content bundled with the task data; always populated, never empty. |
| loading | task-library-cards, attempt-history-list, writing-editor, coming-soon-tabs | ✅ covered | Dismissed — task bank, rubric, and attempt history are synchronous (static bundled data + synchronous `localStorage` reads); no network fetch occurs in this phase, so no loading/skeleton state is needed. |
| error | writing-editor (form) — autosave | 🧪 backstop | `localStorage.setItem` can throw (quota exceeded, private browsing). Resolution copy is defined above (Copywriting Contract "Error state" row); needs a held-out test that forces a `setItem` failure and asserts the warning renders without losing in-memory text. |
| error | attempt-history-list (list-collection) — corrupted storage | ✅ covered | Defensive JSON parse: corrupted `fluentpath.celpip.v1` falls back to a safe empty default instead of crashing — explicit locked decision in CONTEXT.md, mirrors `progress.ts`'s existing try/catch-silent-fallback pattern. |
| populated | task-library-cards (list-collection) | ✅ covered | Grid of ~8 cards per task type; each card shows title, scenario snippet, time limit, and an attempt-status badge (not started / in progress / completed). |
| populated | attempt-history-list (list-collection) | ✅ covered | Reverse-chronological list; each row shows date, duration used, word count, and a "view results" link into that attempt's results state. |
| partial | writing-editor (form) — word count | ✅ covered | Under 150 or over 200 words is a visual flag only (muted → warning color per Color contract); submission is never blocked by word count, matching real CELPIP exam behavior. |
| partial | rubric-checklist (form) | ✅ covered | A partially-checked checklist is a valid, non-blocking, persisted state — no "check all items" gate exists anywhere in this flow. |
| overflow | results-comparison (static-content) | ✅ covered | User text and model answer render in independently scrollable panels with `whitespace-pre-wrap` (same pattern as `WritingDesk.tsx`'s model-answer `<pre>`); neither is ever clipped. |
| overflow | coming-soon-tabs (nav) | ✅ covered | Tabs wrap to a second row on narrow mobile widths (`flex-wrap`); never horizontally clipped or scroll-trapped. |
| overflow | task-library-cards (list-collection) | ✅ covered | Long task titles/scenario text truncate to 2 lines (`line-clamp-2`) on the card; the full untruncated text is always shown on the task detail/simulator page. |
| zero-one-many | attempt-history-list (list-collection) | ✅ covered | Zero → empty-state copy; one → "1 attempt"; many → "{n} attempts"; list always orders most-recent-first. |
| zero-one-many | task-library-cards (list-collection) | ✅ covered | Dismissed — fixed content set (~8 per task type) shipped at launch; count does not vary at runtime in this phase. |
| long-text | writing-editor (form) | ✅ covered | `textarea` is `resize-y` with internal scroll and no max-height cap, so a full 200+ word answer never clips — same as `WritingDesk.tsx` precedent. |
| long-text | results-comparison (static-content) | ✅ covered | Same scrollable/`pre-wrap` handling as the overflow row above — full fidelity to the learner's actual submission is required, so nothing is ever truncated on the results view. |
