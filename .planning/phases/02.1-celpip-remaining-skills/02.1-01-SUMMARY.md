# Phase 02.1 Plan 01: CELPIP Speaking Tracer Summary

One CELPIP Speaking Task 1 prompt runs end to end — silent prep, an automatic
recording start, in-browser playback, a self-evaluation, and an attempt that reaches
Postgres through the unchanged Phase 2 merge contract — with all four of the phase's
architectural risks retired before a word of Reading or Listening content is authored.

## Status: complete — checkpoint approved, with one item owed

All three tasks are done. Task 3's blocking checkpoint was driven by the coordinator through
a real browser against the `npm start` production build and **approved**; the evidence is
recorded verbatim below, including the two things that were *not* observed directly.

**Owed to the phase gate (plan 12): the phone pass.** No device was available. The
`MediaRecorder` container probe is exactly the code path a phone exercises hardest — Safari
before 18.4 returns false for WebM and supports MP4 only — so the probe is untested on the
one browser family it was written for. This is not a claim that it fails; it is a claim that
nobody has looked.

## What shipped

### Task 1 — the CSP fix (commit `07c7986`)

`next.config.ts` gains exactly one directive: `media-src 'self' blob:`. The policy declared
no `media-src`, so it inherited `default-src 'self'`, and `'self'` does not match a `blob:`
URL — the object URL the recorder hands an `<audio>` element would have been refused in
production while working fine under `next dev`.

`scripts/verify-headers.mts` (new, 24 assertions) loads `next.config.ts` under
`--experimental-strip-types`, parses the served CSP into a directive map, and asserts the
widening stayed narrow: `blob:` is present in `media-src` and absent from `script-src` and
`connect-src`; `object-src 'none'`, `frame-ancestors 'none'` and `default-src 'self'` are
unchanged; `microphone=(self)` survives in `Permissions-Policy`.

Parsing into a directive map rather than grepping the whole string is deliberate — the
assertion "`blob:` appears somewhere in the CSP" is exactly the one that would pass while
`blob:` sat in `script-src`.

### Task 2 — the tracer (commit `d059139`)

**Content (all original, D-06).** One Task 1 `advice` prompt at 30s prep / 90s response, and
the Speaking rubric's Task Fulfilment dimension — four items, complete and final, not a
placeholder. Both files open with the originality header `tasks-email.ts` uses. Every rubric
id is prefixed `speaking-` so it cannot collide with an `email-` or `survey-` id in
`checkedRubric`.

**Types.** `CelpipSpeakingShape` and `CelpipSpeakingPrompt` in `src/lib/celpip.ts`, with
`SPEAKING_PROMPTS` / `getSpeakingPrompt` as siblings of `CELPIP_TASKS` / `getTask`.
`CelpipTaskType` was **not** widened. `CelpipRubric` gains a `speaking` key populated by
reference from `rubric-speaking.ts`, so `rubric.ts`'s originality claim still covers exactly
the text `rubric.ts` contains.

**Persistence — the six lockstep sites.** `speakingAttempts:
Record<string, CelpipSpeakingAttempt[]>` through `CelpipProgressState`, `CELPIP_EMPTY`,
`celpipProgressSchema`, `MERGE_CELPIP_EMPTY`, `celpipCoerce` and `mergeCelpip`. The merge
rule is one line — the same `unionRecord(x.f, y.f, (p, q) => canonical([...p, ...q]))` the
writing `attempts` field already uses, so it inherits that proof rather than needing a new one.

**The enum trap was not repeated.** `celpipAttemptEntry` hard-codes the writing task-type
pair independently of the zod enum, which is why a new `taskType` would validate on the wire
and then be silently deleted by the merge. `celpipSpeakingEntry` carries `shape` through as
`str(v.shape) ?? ""` and mirrors **no** list of shapes; the schema declares
`z.string().max(64)`, not an enum. Two assertions — one in each script — say so out loud.

**No second deletable map.** Speaking state is append-only with a natural key
(`promptId` NUL `date`), so it needs no `updatedAt` of its own and cannot fight
`pickDraftsSide` for the single instant this state carries.

**Generalisation for the plans that follow.** `canonicalAttempts` and `celpipAttemptRecord`
became `canonicalEntries` and `entryRecord`, generic over `{ date: string }` with an injected
key function. Behaviour is byte-identical: `verify-merge` reported **4313** immediately after
the refactor and before any new fixture. Listening and Reading now each add one entry
coercer, one key function and one merge line.

**Store, route, component.** `addSpeakingAttempt` routes through `persist` (the single site
that authors the D-01b instant). The route copies the writing route's shape exactly — awaited
`params` Promise, non-async `generateStaticParams`, `notFound()` called not returned, no
`"use client"`, the same `JsonLd` envelope. `SpeakingRecorder.tsx` is a `brief → prep →
respond → review` machine reusing `Timer` and `RubricChecklist` unchanged.

## Mutation testing — and the three defects a first green run hid

A first-run green is not evidence, so every load-bearing rule was mutated. **24 deliberate
defects; 21 were caught immediately, 3 were not.** All three are now closed and re-tested.

An early batch appeared to find gaps that were not real: `progress-schema.ts` is CRLF while
`progress-merge.ts` is LF, so `\n`-anchored replacements against the schema silently no-op'd
and three "surviving" mutations had never been applied. The harness was rewritten to **fail
loudly when a mutation's anchor is not found or is ambiguous**, and every result below is
from that harness. One later mutation also proved to have hit the *writing* coercer instead
of the speaking one because the anchor matched two sites — hence the ambiguity check.

### Caught (21)

CSP: `media-src` dropped · `media-src` without `blob:` · `blob:` added to `script-src` ·
`object-src` loosened · `frame-ancestors` loosened · `default-src` widened · `microphone`
revoked.

Merge: an enum guard added to `celpipSpeakingEntry` · `speakingAttempts` dropped from
`mergeCelpip` / `MERGE_CELPIP_EMPTY` / `celpipCoerce` / `CELPIP_EMPTY` · `speakingAttempts`
selected whole-field on the shared drafts instant · sort removed from `canonicalEntries` ·
de-duplication removed · identity-less entries repaired instead of dropped · natural key
reduced to `promptId` · the coercer spreading unvalidated input · coerce-time canonicalisation
removed · `shape` defaulting to a fabricated value · `durationSeconds` / `sizeBytes` unclamped.

Schema: `speakingAttempts` dropped from `celpipProgressSchema` · `shape` tightened to an enum ·
`note` and `mimeType` unbounded.

### Survived, then closed (3)

1. **Unbounded numerics on the new shape.** Replacing
   `recordingSeconds: z.number().int().min(0).max(MAX_COUNT)` with `z.number()` produced zero
   failures — nothing asserted that a negative, fractional or 1e308 value was refused. Eight
   assertions added covering `recordingSeconds`, `durationSeconds` and `sizeBytes`; the
   mutation now fails, as do the same mutations on the other two fields.
2. **An unclamped `recordingSeconds` in the merge coercer.** No fixture fed the coercer a
   negative. A garbage-entry block now asserts every numeric is clamped, every string falls
   back, both flags coerce to booleans — and that normalising is idempotent, which is what
   stops the reconcile rewriting on every load.
3. **`checkedRubric` spread raw instead of rebuilt via `boolRecord` — in the WRITING coercer,
   and pre-existing.** No writing fixture had ever carried a non-boolean rubric value, so the
   prototype-pollution-adjacent pass-through went unnoticed. Closed with one assertion; see
   Deviations.

### [Judgement call] The response window never pauses, even in practice mode

The plan says to reuse `Timer` unchanged for both countdowns. `Timer`'s practice mode renders
a Pause button, but pausing the countdown while `MediaRecorder` keeps capturing would
desynchronise the timer from the recording. The prep countdown receives the selected `mode`
(pausing to think is useful and harmless); the response countdown always receives
`mode="timed"`. The exam gives no pause there either. The brief states this in one line.

### [Judgement call] The microphone opens on Start and stays open through prep

The plan requires permission to be requested during the brief phase, `getUserMedia` to be
called only from an explicit press, and tracks to be stopped the instant recording ends. All
three are satisfied by acquiring the stream in the Start handler and holding it through prep.
The cost is that the OS microphone indicator is lit during the thinking window; rather than
hide that, the UI says it plainly — "your microphone indicator will be on through the thinking
time; nothing is captured until the countdown reaches zero".

### [Observation, not a deviation] The route is server-rendered on demand, not prerendered

The plan's done criterion says the build "pre-renders the speaking route". `npm run build`
lists `ƒ /celpip/speaking/[promptId]` — **exactly as it lists `ƒ /celpip/writing/[taskId]`**.
`generateStaticParams` is present and correct; the segment is dynamic for a reason that
predates this plan and applies equally to the shipped writing route. Behaviour matches the
established route; no change was made to chase the static marker.

### One false alarm, correctly dismissed

window. It is not: the response timer read 1:15 (15 of 90 seconds consumed) at the stop

reachable only from `beginRecording()`, which only the prep countdown's expiry calls.
