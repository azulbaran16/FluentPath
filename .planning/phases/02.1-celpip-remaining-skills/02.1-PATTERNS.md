### 2. Speaking self-evaluation rubric — `rubric.ts` extension

**Analog:** `src/lib/celpip/rubric.ts:1-7` (authoring) and `RubricChecklist.tsx:8-53` (rendering).

**Authoring pattern** (`rubric.ts:1-25`):

```typescript
import type { CelpipRubric } from "../celpip";

// Self-evaluation rubric, rewritten in our own words from the CELPIP Writing
// level descriptors (…). Every word here is original — no descriptor text or
// third-party study material is reproduced anywhere in this file.
export const CELPIP_RUBRIC: CelpipRubric = {

    {
      key: "task-fulfillment",
      label: "Task Fulfillment",

          explanation:
```

Three structural rules the Speaking rubric must follow:
- `id` is prefixed with the skill (`email-*`, `survey-*` → `speaking-*`). These ids are
  the keys stored in `checkedRubric`, so a collision across skills would cross-contaminate
  attempt history.
- Every item carries BOTH `text` (the yes/no question) and `explanation` (why it matters).
  `RubricChecklist.tsx:43` renders the explanation unconditionally.
- Dimensions mirror the exam's own axes. Writing uses four
  (`task-fulfillment`, `organization`, `vocabulary`, `grammar-format`).

**Rendering — reuse `RubricChecklist` unchanged.** Its props are already skill-agnostic
(`RubricChecklist.tsx:11-16`): `rubric: CelpipRubricDimension[]`, `checked`, `onToggle`.
The only change needed is widening the `CelpipRubric` interface (`src/lib/celpip.ts:30-33`),
which currently hard-codes `email` / `survey` keys.

Note `RubricChecklist.tsx:5-7`: "A partially-checked list is a valid, persisted state on
purpose — no check-all gate exists here or anywhere else in the flow." Do not add a gate.

### 4. `src/components/celpip/ListeningPlayer.tsx` (component, TTS streaming + event-driven)

**Speech analog — this is the pattern to reuse, not reinvent.** The repo has exactly one
speech-synthesis idiom, repeated four times: `ListeningRoom.tsx:68-81`,
`ReadingRoom.tsx:88-95`, `PronunciationLab.tsx:62-67`, `VocabularyView.tsx:95-100`.
The most complete instance, including the `onend` state handoff and the stop path
(`ListeningRoom.tsx:68-81`):

```typescript
function play() {
  if (typeof window === "undefined" || !window.speechSynthesis) return;
  window.speechSynthesis.cancel();
  const u = new SpeechSynthesisUtterance(clip.lines.join(". "));
  u.lang = "en-US";
  u.rate = 0.95;
  u.onend = () => setPlaying(false);
  setPlaying(true);
  window.speechSynthesis.speak(u);
}
function stop() {
  window.speechSynthesis?.cancel();
  setPlaying(false);
}
```

Five conventions this establishes, all mandatory for the new player:
1. Guard with `typeof window === "undefined" || !window.speechSynthesis` — SSR-safe and
   feature-detected in one expression.
2. `cancel()` **before** `speak()`, always. Chrome queues utterances otherwise.
3. `lang = "en-US"`, `rate = 0.95`. Same values everywhere; keep them.
4. `u.onend` drives the `playing` flag back to false — that is the event hook D-05
   needs, since questions are revealed only after playback completes.
5. No `SpeechSynthesis` typings are needed (`speechSynthesis` is in lib.dom).
   `src/lib/speech.d.ts` covers only `SpeechRecognition`, which Listening does not use.

**Phase machine — Listening needs one more phase than Writing.** D-04/D-05 forbid showing
the script or the questions before playback. Extend the Writing union:

```typescript
type Phase = "brief" | "playing" | "answering" | "results";
```

`u.onend` is what advances `"playing" → "answering"`. The transcript reveal reuses
`ListeningRoom.tsx:177-195` — but note the divergence: `ClipPlayer` reveals the transcript
on `Check answers` (`:160-163`) and also offers a `Show transcript` button *before*
answering (`:179-184`). **That pre-answer button must not be copied** — D-04 says
hear-never-read. Keep only the post-submit reveal:

```tsx
<div className="rounded-[var(--radius)] border border-line bg-card p-5 shadow-[var(--shadow-soft)]">
  <h3 className="mb-2 font-display text-base font-semibold">Transcript</h3>
  <div className="space-y-1.5 text-sm leading-relaxed text-ink-soft">
    {clip.lines.map((line, i) => <p key={i}>{line}</p>)}
  </div>
</div>
```

Likewise `ClipPlayer` offers unlimited replay (`:113-118`). The real exam does not.
Under a timed mode, either drop the Replay button or count replays into the attempt record.

**Note area.** No analog exists for a scratch note pad. The nearest is the Writing
`textarea` (`WritingSimulator.tsx:299-308`) — copy its class string and its autosave
treatment, but see the persistence section: notes are transient and must be cleared in
`finalizeAttempt`, exactly as `clearDraft` is.

## Shared Patterns

### Persistence contract — what a new attempt shape MUST do

This is the highest-risk area of the phase. Three files change in lockstep, and two
verification scripts gate the result.

**Source A — the schema** (`progress-schema.ts:426-446`):

```typescript
export const celpipAttemptSchema = z.object({
  taskId: z.string().max(200),
  taskType: z.enum(["email", "survey"]),
  date: z.string().max(64),
  durationSeconds: z.number().int().min(0).max(MAX_COUNT),
  wordCount: z.number().int().min(0).max(MAX_COUNT),
  text: celpipText,
  checkedRubric: sanitizedRecord(z.boolean()),
  outOfTime: z.boolean(),
});

export const celpipProgressSchema = z.object({
  attempts: sanitizedRecord(sanitizedArray(celpipAttemptSchema)),
  drafts: sanitizedRecord(celpipText),
  updatedAt: instantOrNull,
});
```

Constraints this imposes on any new attempt shape:

1. **`taskType` is a hard literal enum, mirrored in two places.** Adding a Reading/
   Listening/Speaking attempt kind means extending `z.enum([...])` here AND the runtime
   guard in `progress-merge.ts:672`
   (`if (taskType !== "email" && taskType !== "survey") return null;`). Miss the second
   and every new attempt is silently dropped by the merge on the first reconcile.
2. **A compile-time drift guard will catch you** (`progress-schema.ts:471-474`):
   `CELPIP_SCHEMA_MATCHES_STATE` asserts `Identical<z.output<typeof celpipProgressSchema>,
   CelpipProgressState>`. Interface and schema must move together or `tsc --noEmit` fails.
   This is a feature — use it.
3. **`taskType` is deliberately NOT imported as a value** (`progress-schema.ts:118-130`).
   `type CelpipTaskType = import("./celpip").CelpipTaskType;` is an erased type-only
   import so the module's only runtime dependency stays zod. Any new skill union must be
   referenced the same way. Do not add a runtime import to `src/lib/celpip.ts` here.
4. **`progress-merge.ts` may have no runtime relative imports at all**
   (`progress-merge.ts:65-67`): "no react, no next, no `@/` aliases and no runtime
   relative imports, so `node --experimental-strip-types` can load it directly." The
   `MERGE_CELPIP_EMPTY` literal (`:632-636`) is a deliberate second declaration for
   exactly this reason. If `CELPIP_EMPTY` gains a field, add it to both.
5. **Additive only (D-08).** `celpipProgressSchema` is built from the *plain* object
   constructor, which strips unknown keys. Existing stored blobs keep parsing because
   every new field must be optional-or-defaulting. Never widen with a strict constructor.
6. **New free-form text needs a bound.** `celpipText` is `z.string().max(CELPIP_MAX_TEXT)`
   with `CELPIP_MAX_TEXT = 20_000` (`:396-398`), and over-length entries are *rejected*
   rather than truncated (`:384-386`) — a truncated essay would read as the learner's own
   work. Listening notes and Speaking self-notes fall under the same rule.

**Source B — the merge** (`progress-merge.ts:799-813`):

```typescript
export function mergeCelpip(a: unknown, b: unknown): CelpipProgressState {
  const x = celpipCoerce(a);
  const y = celpipCoerce(b);
  return {
    attempts: unionRecord(x.attempts, y.attempts, (p, q) => canonicalAttempts([...p, ...q])),
    drafts: pickDraftsSide(x, y) >= 0 ? { ...x.drafts } : { ...y.drafts },
    updatedAt: laterInstant(x.updatedAt, y.updatedAt),
  };
}
```

Rules a new attempt shape must survive:

- **Natural key** (`progress-merge.ts:698-700`): `` `${e.taskId}\0${e.date}` ``. An attempt
  with no `taskId` or no `date` is dropped (`:671`) because it cannot be de-duplicated and
  would be re-appended on every reconcile. Every new attempt kind must carry both.
- **Canonical ordering is a correctness requirement, not cosmetics**
  (`progress-merge.ts:702-729`). `canonicalAttempts` de-dupes by key then sorts by `date`,
  falling back to the entry's canonical form. Without a total order the reconcile finds a
  diff on every page load and writes forever.
- **`celpipAttemptEntry` must be extended** (`:666-685`). It hand-normalises every field;
  a new field it does not know is *deleted on merge* even though the zod schema accepted
  it. Coercion must be idempotent (`coerce(coerce(x)) === coerce(x)`), so assign optional
  fields only when present — see the identical rule at `:241-247`.
- **The three algebraic properties** are asserted by `scripts/verify-merge.mts`
  (see `:1134-1148`, which cross-products every named CELPIP state). New shapes must be
  added to the `celpipStates` fixture list (`:1121-1132`) or the new fields go untested.
- **Any new map with a real delete site needs the whole-field instant rule.**
  `drafts` is the current example, and `pickDraftsSide` (`:785-797`) documents exactly why
  a key union would resurrect a cleared draft — the fca41b7 defect. If Listening notes are
  persisted at all, they belong in the same whole-field family, not in a key-unioned map.

**Source C — the store** (`celpip-progress.ts:261-272`):

- **Every mutation goes through `persist`** (`celpip-progress.ts:187-199`), which is the

  surface a visible warning rather than dropping silently (`saveDraft` `:276-283`,
  consumed at `WritingSimulator.tsx:58-65` and rendered at `:310-320`). Any new
  autosave path owes the learner the same warning.
- **Nothing is ever mutated in place**; attempts append to a per-task array.

**Gates.** `scripts/verify-merge.mts` and `scripts/verify-schema.mts` must still pass.
`verify-merge.mts:1029-1230` is the CELPIP section — read it before touching the schema,

- **Reset on a changed `totalSeconds`** (`:40-46`): a new task resets the whole countdown.

- **`onExpire` fires exactly once**, guarded by `expiredRef` (`:72-76`), and the latest

### Design tokens

**Source:** `src/app/globals.css:8-30` (`:root`), `:33-53` (`.dark`), `:55-76` (`@theme inline`).

Tokens are declared once as CSS variables and re-exposed as Tailwind utilities by
`@theme inline` (`globals.css:55-76`). That is why `text-ink-soft`, `border-line-strong`,
`bg-paper-deep`, `text-sky`, `text-teal`, `text-vermilion`, `font-display` and
`font-sans` all work as utilities. Consequences for new components:

- **Never hard-code a hex.** Both light and dark palettes are variable-swapped
  (`:33-53`); a literal colour breaks dark mode silently.
- **Two access styles, both correct and both in use.** Static colours go through the
  Tailwind utility (`text-sky`); *computed* or conditional colours go through inline
  `style` with `var(--…)` — see `Timer.tsx:115` (`color: isWarning ? "var(--vermilion)" : undefined`)
  and `WritingSimulator.tsx:180` (`style={{ background: "var(--sky)" }}`).
- **Tints use `color-mix`**: `` `color-mix(in srgb, ${accent} 14%, transparent)` `` for icon
  chips (`TaskCard.tsx:56`, `ListeningRoom.tsx:46`) and `10%` for answer-state fills
  (`ReadingRoom.tsx:160-162`).
- **Radius and shadows are tokens too**: `rounded-[var(--radius)]`,
  `shadow-[var(--shadow-soft)]`, `shadow-[var(--shadow-lift)]` on hover.
- **Semantic colour assignments already established:** `--sky` is the CELPIP accent
  throughout (`TaskCard.tsx:39`, `CelpipTabs.tsx:34`, `celpip/page.tsx:50-51`);
  `--teal` = correct; `--vermilion` = wrong / urgency; `--gold`, `--plum`, `--moss` are
  unused by CELPIP and available if the skills need distinct accents.
- **Headings are `font-display`** (Fraunces) with `font-semibold`; body copy is
  `text-ink-soft` / `text-muted`.
- **Entrance animation**: the `rise` class (`globals.css:106-112`) with a staggered
  `animationDelay` on grids (`TaskCard.tsx:46`).

### Error / degradation handling

- **Never throw on stored data.** `safeReadCelpip` (`progress-schema.ts:450-462`) and
  `readLocal` (`celpip-progress.ts:58-65`) both degrade to `CELPIP_EMPTY`.
- **A failed local write is surfaced, never swallowed** (`celpip-progress.ts:71-78` →
  `WritingSimulator.tsx:310-320`).
- **A failed reconcile is silent and harmless** (`celpip-progress.ts:239-241`):
  "a failed reconcile must never degrade the local session."
- **Feature-detect browser APIs** rather than assuming (`ListeningRoom.tsx:69`).
