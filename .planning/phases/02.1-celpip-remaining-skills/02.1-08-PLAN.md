<objective>
Build the Reading section's machinery: the content types, the persistence field, the
drop-down-blank control, and the runner — on an empty bank, so the expensive part (authoring
~2,500 words and 38 items) can land as pure content in the two plans after this one.

Purpose: a Reading section built only from four-option multiple choice would look nothing
like the real exam. The drop-down blank appears in three of the four parts, it is the type
learners most often meet cold on exam day, and its difficulty is specific — the wrong options
are grammatically fine and only contextually wrong. It has to be a first-class control, not
an afterthought bolted onto an MCQ list, and that is why it gets built before any passage is
written.

Output: `/celpip/reading/{setId}` exists and works, `readingAttempts` is in the persistence
contract, and adding a reading part becomes a pure append.

`READING_SETS` is still empty and the landing still reports Reading as unavailable, truthfully.
Plans 08 and 09 are a pair, exactly as 04 and 05 were; plan 09 is small because this plan
exists.

    for the originality check, accessible to a screen reader, and costs no asset pipeline —
    which is a cost this phase cannot absorb three weeks out.

    A `CelpipReadingPart` carries an `id`, its `kind`, a `title`, a `minutes` allowance, an
    optional passage, an optional diagram, an optional blank-bearing text, and its plain
    questions. **Reading is timed per part in the real exam, not as one block**, and the
    allowances are confirmed against the beta user's official format material: 11 minutes for
    correspondence, 8 for the diagram, 9 for information, 11 for viewpoints — 39 minutes and 38
    questions for the whole set. Carry `minutes` on the part so the runner can arm the timer
    per part and so the set's total is derived rather than typed twice. A
    `CelpipReadingSet` carries `id`, `title`, a derived or asserted `timeLimitMinutes`, and
    `parts`. Add
    `READING_SETS` (empty here), `getReadingSet(setId)` and a part-kind label lookup as
    siblings of the existing exports. Do not author content in this plan.

    `CelpipReadingAttempt` with `setId`, `date`, `durationSeconds`,
    `answers` (item id to chosen option index, covering both question ids and blank ids),
    `correct`, `total` and `outOfTime`, then run it through the same six lockstep sites the
    previous two fields went through: interface, `CELPIP_EMPTY`, `celpipProgressSchema`,

    `DropdownBlank` renders one blank inline inside prose: a native `select` carrying the
    blank's options, with an accessible label naming which blank it is, disabled once the set
    is submitted, and taking a teal or vermilion treatment after submit exactly as the
    multiple-choice options do. Use a native select rather than a custom listbox — it is
    keyboard- and screen-reader-correct for free, it behaves properly on a phone, and the exam
    itself uses a drop-down. After submit, render the correct option and the blank's
    explanation beneath or beside the sentence it sits in, so the learner sees why the option
    that felt right was contextually wrong. That contextual-not-grammatical distinction is the
    whole difficulty of this question type.

    `ReadingRunner` is a client component on the Writing simulator's state machine: a phase of
    reading then results, a mode of timed or practice, `startedAt`, `expired`, `locked`,
    `finalizedRef`. Reuse `Timer` unchanged with the sticky-header wrapper, and put the
    two-way expiry exit on screen — submit as-is or continue untimed — never discarding her
    work.

    **The timer is armed per part, not once for the whole set**, because that is how the real
    exam paces it and because a single 39-minute block lets a learner overspend on the
    correspondence part and then run out on viewpoints — precisely the failure the per-part
    allowance exists to train against. Use `Timer`'s documented reset-on-changed-`totalSeconds`
    behaviour to re-arm as the learner moves from part to part, feeding it the part's `minutes`.
    Expiry of one part offers the same two-way exit and then advances; it never discards.

    Render the four part kinds from one component: a passage as prose, a diagram as an
    accessible table or definition list built from the structured data, a blank-bearing text
    as prose with `DropdownBlank` inline, and plain questions as the option-button list. Copy
    `ReadingRoom`'s grading treatment verbatim — the same class strings, the same
    teal-for-correct and vermilion-for-wrong `color-mix` fills, the same check and cross icons,
    the same disabled-after-submit rule.

    **Diverge from `ReadingRoom` on one point deliberately:** it disables submit until every
    question is answered. Do not. The house rule is never to block submission on a quality
    signal, and under exam conditions an unanswered item is a real outcome. Allow submit and
    score blanks as wrong.

    Scoring is objective-key comparison over one answers map covering both questions and
    blanks — the same one-line filter shape `ReadingRoom` already uses. Per D-02 no AI is
    involved anywhere; an answer key is not the automated scoring D-02 forbids. Every item
    shows what she chose, what was correct, and the authored explanation (CELPIP-06 requires
    per-question explanations).

    `finalizeAttempt` copies the once-only guard and is wired to every exit path out of the
    results view — the retry button and the back link's onClick — with the ref reset on retry.

    The route file mirrors the writing route: non-async `generateStaticParams` over
    `READING_SETS` (which returns an empty array today and that is fine), an async page whose
    `params` is a Promise that is awaited, `notFound()` called rather than returned, no
    `"use client"` on the route, and the `JsonLd` LearningResource envelope with `teaches` set
    to CELPIP Reading.

    Design tokens only — no hard-coded hex, `--sky` accent, teal for correct, vermilion for
    wrong, `font-display` headings, `rounded-[var(--radius)]` panels with
    `shadow-[var(--shadow-soft)]`.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-36 | Tampering / XSS | rendering passages or diagram cells as raw HTML for formatting convenience | high | mitigate | No `dangerouslySetInnerHTML` anywhere in the CELPIP components; formatting is expressed as structured data (paragraph arrays, table rows), and a grep gate proves it — the same gate Phase 1 used |
| T-02.1-37 | Tampering | `readingAttempts` merged by a non-associative rule | critical | mitigate | Reuses the existing `unionRecord` plus canonical-entries rule proven by the O(n^3) sweep; new fixtures added to `celpipStates` |
| T-02.1-38 | Tampering | prototype pollution via answer-map keys | medium | mitigate | `answers` goes through `sanitizedRecord`, which assembles a fresh object and skips poisoned keys |
| T-02.1-39 | Tampering | a blank id colliding with a question id in the shared answers map | medium | mitigate | Ids must be unique within a set; the constraint is documented on the type and gated by the harness in plan 09 |
| T-02.1-40 | Denial of service | attempt payload growth | low | mitigate | The attempt holds a bounded integer map plus counters; the 2 MiB headroom measured in plan 01 covers all four records |
| T-02.1-41 | Information disclosure | answer key in the client bundle | low | accept | Practice, not certification; the shipped practice rooms already grade client-side |
| T-02.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero packages. A native `select` is used precisely so no combobox library is needed |
