# Phase 02.1 Plan 04: Listening Infrastructure Summary

The Listening section's foundations: speaker-turn content types with a reserved slot for
recorded audio, a third append-only field through the Phase 2 merge contract, one module
that owns every `speechSynthesis` landmine in the section, and the audio check that stops a
learner being stranded by the two decisions this section is built on.

## Status: complete — and deliberately invisible

Both tasks executed, verified and committed. Every `<verify>` block ran.

**Nothing here is visible to the learner, and that is the plan's own stated outcome.** Plan
05 is what makes Listening usable, and it is small because this plan exists. `/celpip` still
reports Listening as "Not yet available" — correctly, since `LISTENING_SETS` is empty and
`section()` derives availability from bank contents.

## What shipped

### Task 1 — content types and the persistence field (commit `26b594f`)

**The content types, in `src/lib/celpip.ts`** — the record plan 05 needs, so it does not have
to re-derive them:

```ts
export type CelpipListeningPartKind =
  | "problem-solving" | "daily-conversation" | "information"
  | "news-item" | "discussion" | "viewpoints";

export interface CelpipListeningTurn    { speaker: string; text: string }
export interface CelpipListeningSegment { id: string; turns: CelpipListeningTurn[]; audioUrl?: string }

export interface CelpipObjectiveQuestion {
  id: string; stem: string; options: string[];
  answer: number;            // index into options
  explanation: string;       // REQUIRED — see below
  segmentId?: string;
}

export interface CelpipListeningPart {
  id: string; kind: CelpipListeningPartKind; title: string;
  segments: CelpipListeningSegment[];        // an ARRAY on every part, always
  questions: CelpipObjectiveQuestion[];
}

export interface CelpipListeningSet {
  id: string; title: string; timeLimitMinutes: number; parts: CelpipListeningPart[];
}

export const LISTENING_SETS: CelpipListeningSet[];                 // empty — plan 05 fills it
export function getListeningSet(setId: string): CelpipListeningSet | undefined;
export function listeningPartKindLabel(kind: CelpipListeningPartKind): string;
export const CELPIP_LISTENING_PART_KINDS: CelpipListeningPartKind[];
```

Four decisions inside that shape are load-bearing rather than stylistic:

- **A script is turns, not a string.** One choice solves four problems: it keeps every
  utterance far under Chrome's ~15-second truncation point without a timer hack; it gives the
  multi-speaker parts genuinely distinct voices, which is what those parts test; it makes the
  post-answer transcript renderable with speaker labels for free; and it puts `audioUrl` in an
  obvious per-segment home.
- **`audioUrl?` is the whole of D-03's reversibility, in one optional field.** Absent from
  every segment today. When VOICE-01 lands, a segment gains a file path and the player prefers
  it — no stored attempt changes shape, nothing migrates, and a same-origin file needs no CSP
  change because `default-src 'self'` already covers it.
- **`explanation` is required, not optional.** CELPIP-06 and CELPIP-07 both ask for
  per-question explanations. An optional field is one an author forgets under deadline; the
  compiler is a cheaper reviewer than a human reading 37 items.
- **Every part carries an array of segments**, though only problem solving has more than one.
  A bare-field special case would live forever in the one component where a mistake means the
  learner hears nothing and — under D-05 — never sees a question either.

`CELPIP_LISTENING_PART_KINDS` is **derived** from the label table's key order rather than
written out twice, so plan 05's "n of 6" coverage line cannot go stale. The label table is a
total `Record` over the union, so a seventh kind fails `tsc` rather than rendering a blank
heading.

**Persistence — the six lockstep sites.** `listeningAttempts:
Record<string, CelpipListeningAttempt[]>` through `CelpipProgressState`, `CELPIP_EMPTY`,
`celpipProgressSchema`, `MERGE_CELPIP_EMPTY`, `celpipCoerce` and `mergeCelpip`. The merge rule
is one line — the same `unionRecord(x.f, y.f, (p, q) => canonical([...p, ...q]))` the writing
and speaking fields already use, so it inherits their proof rather than needing a new one.
That is exactly the payoff plan 01 bought by generalising `canonicalEntries`/`entryRecord`.

```ts
export interface CelpipListeningAttempt {
  setId: string; date: string;          // the natural key, joined on a NUL
  durationSeconds: number;
  answers: Record<string, number>;      // question id -> chosen option index
  correct: number; total: number;
  replays: number;                      // "plays once" cannot be ENFORCED, so it is RECORDED
  audioFailed: boolean;                 // she reported hearing nothing and went on anyway
  outOfTime: boolean;
}
```

`taskType` was **not** widened, and nothing in `celpipListeningEntry` mirrors a list of set
ids or part kinds. A set cut from the phase for the calendar must never delete a result the
learner already has — the same guarantee `shape` carries for Speaking, one level out.

**Notes are not persisted, and both halves of the contract now say so out loud.** The
player's note-taking area lives in React state and dies with the set. Persisting it would
create a second map with a real delete site riding the one `updatedAt` this state carries,
which `pickDraftsSide` already rides — and a device stamping while saving a note would then
also win the `drafts` map, resurrecting a cleared writing draft (the `fca41b7` defect). The
reasoning is recorded in a comment on the attempt type, in a comment on
`addListeningAttempt`, and — more usefully — in an assertion in **each** script that a client
sending a `notes` field has it stripped. Without those, the argument quietly stops being true
the first time a future component sends the field speculatively.

**Answer indexes are dropped, never clamped.** `answers` is
`sanitizedRecord(z.number().int().min(0).max(CELPIP_MAX_OPTION_INDEX))` on the schema side and
a rebuilt map on the merge side. An index that is negative, fractional, non-finite, a string,
or past the ceiling costs **only itself** — the attempt is still stored and the rest of the
sheet still scores. Clamping was rejected explicitly: a clamped index is an answer she never
chose, shown back to her in her own history with no way to tell.

**Fixtures, not one-off assertions.** Five new states went into `celpipStates` —
`listeningOnly`, `allThreeSkills`, `listeningTwins`, `listeningDeafOnly` and
`legacyNoListeningField` — so the O(n³) sweep exercises each against every other under both
bracketings. That single edit is most of the jump from **6,994 to 12,040** assertions.
`legacyNoListeningField` is the row shape sitting in Postgres *right now*: written between
plan 01 and this one, so `speakingAttempts` present and `listeningAttempts` **absent** rather
than empty. `legacyNoSpeakingField` (the Phase-1 shape, missing both) is kept alongside it.

### Task 2 — the speech driver, the audio check, and a gate for both (commit `bc2215b`)

**`src/lib/celpip-speech.ts` — the exported surface** (the second record plan 05 needs):

```ts
export interface CelpipSpeechTurn { speaker: string; text: string }
export type SpeechFailureReason = "engine" | "interrupted" | "unsupported";
export interface SpeakerVoice { voice?: SpeechSynthesisVoice; pitch: number }

export function speechSupported(): boolean;                      // call from an effect, not render
export function useEnglishVoices(): SpeechSynthesisVoice[];      // cancels on teardown
export function planVoices(speakers: string[], voices: SpeechSynthesisVoice[]): Map<string, SpeakerVoice>;
export function speakTurns(turns: CelpipSpeechTurn[], options?: {
  voices?: SpeechSynthesisVoice[];
  onStarted?: () => void;
  onCompleted?: () => void;                                       // D-05's ONLY signal
  onFailed?: (reason: SpeechFailureReason) => void;
}): boolean;                                                      // false = nothing to play, or no engine
export function cancelSpeech(): void;                             // neither completion nor failure
```

`speakTurns` **must be called from a user gesture**: every utterance is handed to `speak()`
synchronously inside the one call, which is what keeps the whole sequence inside the gesture
iOS Safari requires. A call chained from a previous utterance's `onend` is no longer part of
one — and chaining is the obvious refactor, which is precisely why it is now gated.

`onCompleted` is attached to the **last** utterance and nowhere else. Under D-05 that callback
is the only thing permitted to reveal the questions, so attaching it to every utterance would
show them after the first line of a six-minute part.

Three quieter rules, each of which produces a visible defect if dropped:

- **A deliberate cancel is not a failure.** The engine raises `error: "canceled"` on *every*
  queued utterance when cancelled, so an unfiltered `onerror` shows the learner a fault every
  single time she leaves the page.
- **Hiding the page stops playback and says so.** Safari can wedge its synthesizer when
  backgrounded mid-utterance until the page is reloaded. `speakTurns` installs a
  `visibilitychange` listener for the duration, cancels on hide, and reports `"interrupted"` —
  rather than pretending playback carried on and letting her answer questions on audio she
  never heard. The listener is removed the moment playback settles, by any route.
- **Voices are a preference.** Deterministic assignment (the pool is sorted by name first,
  because `getVoices()` order is not stable), distinct voices where the browser offers enough,
  and a per-speaker pitch offset plus the on-screen label where it does not. `getVoices()` is
  never awaited and never gates playback.

**No `pause()` and no `onboundary`.** Both are *documented as prohibited* in the module
header, not merely absent — on Android `pause()` is implemented as cancel with an unreliable
`paused` flag, and `onboundary` is not fired on Android and is unsupported for many voices.
Practice mode pauses the **timer**, which `Timer` already supports; `AudioCheck`'s brief says
in words that the audio itself cannot be paused.

**`src/components/celpip/AudioCheck.tsx`** is the unscored warm-up — the exam opens Listening
with one too — and this section's failure valve. It plays a short **two-speaker** original
line from a deliberate press (two speakers on purpose: if only one voice comes through, that
is worth discovering here rather than in Part 1), then offers one explicit branch.

The "heard nothing" branch leads to four real places: a retry, the iPhone hardware
silent-switch note in plain language, the words themselves on request, and
`onDone("no-audio")` so the set can run with the scripts written out. An engine failure lands
in the same branch with one extra sentence, because the learner experiences the two
identically. A browser with no speech engine at all gets its own screen rather than a retry
loop that cannot succeed. Nothing is scored, nothing is persisted, and the outcome
(`"heard" | "no-audio" | "skipped"`) is handed up for plan 05 to arm the timer from.

**`scripts/verify-celpip-speech.mts` (50 assertions, new)** drives the driver against a mock
engine, in the established posture — plain node under `--experimental-strip-types`, no test
runner, no new dependency, `.mts`, explicit `.ts` import extensions. It exists because the
four rules above are invisible to `tsc`, invisible to lint, and invisible in a desktop
browser: they only show up on an iPhone, on Android, or on a script long enough to hit
Chrome's truncation point.

### Survived, then closed (1)

**A missing voice assignment could be dereferenced without a single failure.** Replacing
`if (assigned?.voice) utterance.voice = assigned.voice;` with `utterance.voice =
assigned!.voice!;` passed everything. The reason it matters: a turn whose `speaker` is the
empty string gets **no entry in the plan at all**, so `plan.get(...)` returns `undefined` and
the non-optional form throws — inside the click handler, so the learner gets silence with no
error state and, under D-05, no questions either. An unlabelled narrator line is exactly how
that arrives. Four assertions now cover it (a turn with no speaker label does not throw, still
plays, gets the browser default, and its labelled neighbour is still voiced); the mutation now
fails.

### Survived, and correctly so (2)

1. **`if (active === handle) active = null;` → `active = null;`** is an **equivalent mutant**.

   is recorded here rather than papered over with an assertion that cannot fail.
2. **`setId: z.string().max(200)` → `z.string()`** — the id length bound is untested. Left as
   a known gap: the same bound on `taskId` and `promptId` is equally untested, and adding a
   one-off here without the other two would be decoration.

## Deviations from Plan

### [Rule 1 — pre-existing defect in a file this plan modifies] The merge assigned poisoned record keys the schema strips

**Found by** the new listening assertion "poisoned question ids are dropped", which failed on
the first run.

`progress-schema.ts` has skipped `__proto__`, `constructor` and `prototype` in
`sanitizeEntries` since it was written. **None** of the seven coercion functions in
`progress-merge.ts` did — every poisoned-key assertion in either script exercised the zod path
only, so nothing noticed.

It is not merely untidy. `constructor` and `prototype` were assigned as ordinary own keys by
the merge and stripped by the schema, so **the two halves of one contract disagreed**: the
reconcile finds a difference, sends it, has it stripped server-side, and finds the same
difference on the next load — a write on **every authenticated page view, forever**, for any
account whose blob ever picked one up. Confirmed by direct probe before the fix
(`merge(coerced) equals schema(coerced)? false`) and after (`true`).

- **Fix:** a `POISONED_KEYS` set in `progress-merge.ts` (a deliberate second copy, for the same
  reason `MERGE_EMPTY` is one — this module takes no runtime import), applied in `flagRecord`,
  `numberRecord`, `srsRecord`, `attemptRecord`, `stringRecord`, `boolRecord`, `indexRecord` and
  `entryRecord`.
- **Coverage:** eleven new assertions across both domains — CELPIP drafts, attempts, speaking,
  listening and a rubric map; progress `completed`, `skillXp`, `vocab`, `srs` and `attempts` —
  plus a check that no prototype was polluted. Two mutations (narrowing the set, and dropping
  the guard from `entryRecord`) both fail.
- **In scope** because it is in a file this plan modifies, it was found by this plan's own new
  rule, and `indexRecord` needed the guard regardless — a guarded new coercer sitting beside
  seven unguarded twins would have been the more confusing outcome.
- **Files:** `src/lib/progress-merge.ts`, `scripts/verify-merge.mts` · **Commit:** `26b594f`

### [Rule 1 — defect in my own first draft] Raw NUL separators made `progress-merge.ts` a binary file

The repo's canonical key separator is a literal NUL, and `progress-merge.ts` carried four of
them — which is why git reported the whole file as **binary**. Adding `listeningKey` would have
made five, and this plan's 125-line diff to that file would have been unreviewable, as would
plan 09's when it adds the reading twin.

All five are now written as the `\u0000` escape. **Identical at runtime** (verified: 12,040
assertions pass, including every natural-key and de-duplication assertion), and the file is
text to git again — this plan's diff to it reads as `125 +++`, not as `Bin`. Same fix plan 02
applied to `CelpipLanding.tsx` for the same reason.

Worth recording as a live hazard: writing `\u0000` in an edit produced a **raw NUL byte** in
the file rather than the escape sequence. The conversion had to be done by script.

### [Rule 2 — the gate as written could not distinguish use from documentation] The `onboundary` grep was tightened

The plan's gate is `grep -n "onboundary" … | wc -l | grep -qx 0`. It **fails** against this
driver — because the driver *documents* why `onboundary` must never be used, in the header
comment that also documents the `pause()` prohibition.

Deleting the word to satisfy a literal grep would have removed the only explanation a future
contributor will read before reaching for it to build a progress bar. This is plan 03's lesson
in the opposite direction: there, a single-token gate passed because a **verb** matched; here,
a single-token gate fails because a **comment** matches. The replacement is strictly stronger
and is a conjunction:

```bash
# no non-comment line may mention onboundary, and none may call pause()/read .paused
grep -nE "onboundary" $F | grep -vE "^[^:]+:[0-9]+:[[:space:]]*(//|\*|/\*)" | wc -l   # 0
grep -nE "\.pause\(|\.paused" $F | grep -vE "^[^:]+:[0-9]+:[[:space:]]*(//|\*|/\*)" | wc -l  # 0
# and the prohibition must BE documented
grep -c "onboundary" src/lib/celpip-speech.ts   # 2
grep -c "pause()"    src/lib/celpip-speech.ts   # 1
```

All four pass. The original `pause` and `cancel()`-count gates were run unmodified and pass
(0 matches; 5 `cancel()` sites).

### [Rule 2 — missing critical verification] `scripts/verify-celpip-speech.mts` was added

Not in the plan's `files_modified`. The plan's `<done>` asserts four behavioural properties of
the driver — queued inside one call, never chained from `onend`, never paused, never awaiting
voices — and **nothing in the build would have noticed any of them being broken**. `tsc` is
perfectly happy with a chained `onend`; lint is happy with `onCompleted` on every utterance;
a desktop browser is happy with both. Plan 05 builds the entire player on this module.

50 assertions, mock engine, same no-runner no-dependency posture as the other six scripts. 22
mutations against it; 21 caught, 1 equivalent mutant.

### [Judgement call] `verify-celpip-content.mts` was NOT touched

Plan 03's handoff names plans 04 and 07 as its append targets. This plan authors **no

### [Judgement call] `CELPIP_MAX_OPTION_INDEX = 31`

Not specified by the plan (`max(...)`). An objective question offers four options; 31 is two
orders of magnitude of headroom on a value that is only ever an array index, and it bounds
what a hostile client can store mid-sheet. The merge's copy is asserted equal to the schema's,
and a mutation moving either one fails.

### [Observation, not a deviation] The ledger CLI works again, because the file was normalised

`Ledger frontmatter line is not key: value: "last_updated: …\r"`. The cause is confirmed:
`.planning/WINDOWS.md` had **mixed** line endings. Normalising the file to LF — which changes
nothing in git, since git stores LF in the index for text files — made the CLI work, and both
of this plan's entries were appended by the tool rather than by hand. The JSON block re-parses
