# Phase 02.1 Plan 08: Reading Infrastructure Summary

The Reading section's machinery on an empty bank: the four-part content types with a
structured-data diagram, a fourth append-only field through the Phase 2 merge contract, the
drop-down blank as a real gradable control, and a runner that arms the clock per part and
grades questions and blanks through one code path.

## Status: complete — and deliberately invisible

Both tasks executed, verified and committed. Every `<verify>` block ran.

**Nothing here is visible to the learner, and that is the plan's own stated outcome.**
`READING_SETS` is empty, so `/celpip` still reports Reading as "Not yet available" —
correctly, because `section()` derives availability from bank contents — and every
`/celpip/reading/{id}` URL 404s. Plan 09 is what makes Reading usable, and it is small
because this plan exists.

## What shipped

### Task 1 — content types and the persistence field (commit `e163f9f`)

**The content types, in `src/lib/celpip.ts`.** The record plans 09 and 10 need, verbatim, so
they do not have to re-derive it. **Every field name below is pinned** — plans 09 and 10
hard-code them in their verify commands.

```ts
export type CelpipReadingPartKind =
  | "correspondence" | "diagram" | "information" | "viewpoints";

export interface CelpipReadingBlank {
  id: string; options: string[];
  answer: number;            // index into options
  explanation: string;       // REQUIRED — see below
}

export type CelpipReadingTextSegment =
  | { kind: "text"; text: string }
  | { kind: "blank"; blankId: string }
  | { kind: "break" };

export interface CelpipReadingBlankText {
  title?: string; intro?: string[];
  segments: CelpipReadingTextSegment[];
  blanks: CelpipReadingBlank[];
}

export interface CelpipReadingPassageSection { label: string; paragraphs: string[] }
export interface CelpipReadingPassage {
  title?: string; paragraphs: string[]; sections?: CelpipReadingPassageSection[];
}

export type CelpipReadingDiagramKind = "schedule" | "fee-table" | "rules-list";
export interface CelpipReadingDiagramRow { label: string; cells: string[] }
export interface CelpipReadingDiagram {
  kind: CelpipReadingDiagramKind; caption: string;
  headers?: string[];            // absent -> renders as a definition list
  rows: CelpipReadingDiagramRow[];
  notes?: string[];
}

export interface CelpipReadingPart {
  id: string; kind: CelpipReadingPartKind; title: string;
  minutes: number;               // PER PART — 11 / 8 / 9 / 11
  instructions?: string;
  passage?: CelpipReadingPassage;
  diagram?: CelpipReadingDiagram;
  blankText?: CelpipReadingBlankText;
  questions: CelpipObjectiveQuestion[];   // SHARED with Listening, not copied
}

export interface CelpipReadingSet { id: string; title: string; parts: CelpipReadingPart[] }

export const READING_SETS: CelpipReadingSet[];                  // empty — plan 09 fills it
export function getReadingSet(setId: string): CelpipReadingSet | undefined;
export function readingPartKindLabel(kind: CelpipReadingPartKind): string;
export const CELPIP_READING_PART_KINDS: CelpipReadingPartKind[];
export function readingSetMinutes(set: CelpipReadingSet): number;        // 39 for a full set
export function readingSetItemCount(set: CelpipReadingSet): number;      // 38 for a full set
export function readingPartItemCount(part: CelpipReadingPart): number;   // questions + blanks
```

Five decisions inside that shape are load-bearing rather than stylistic:

- **A blank belongs INSIDE its text.** `blankText` is an ordered array of segments — prose
  runs, blank references and paragraph breaks — so the reply renders as one continuous piece
  of writing with the selects sitting in it. This type's whole difficulty is that the wrong
  options are *grammatically fine and only contextually wrong*; moving the blanks out into a
  numbered list underneath would remove the very context being tested.
- **`CelpipObjectiveQuestion` is shared with Listening, not copied for Reading.** A blank and
  a question are the same act — choose an option index, compare it to a key — so both grade
  through one list and one answers map, and the scoring line is the one-line filter the
  shipped practice room already uses.
- **The diagram is structured data, not an image.** Authorable in the content module beside
  everything else; greppable for the D-06 originality check, which an image is not; a real
  `<table>` with `<caption>` and `<th scope>` for a screen reader; and no asset pipeline,
  which is a cost this phase cannot absorb three weeks out.
- **`minutes` is per PART.** The exam paces Reading part by part, and that is what the section
  trains: a single 39-minute block lets a learner overspend on correspondence and then run out
  on viewpoints, which is precisely the failure the per-part allowance exists to prevent her
  discovering on the day.
- **`explanation` is required at the type level** on both the question and the blank. On the
  blank it is doing the most work in the whole section — it is the only place she is told why
  the option that read perfectly well was still wrong.

`CELPIP_READING_PART_KINDS` is **derived** from the label table's key order rather than
written out twice, and the label table is a total `Record` over the union, so a fifth kind
fails `tsc` rather than rendering a blank heading.

**The set carries no `timeLimitMinutes` field.** The plan allowed "a derived or asserted"
total; deriving it via `readingSetMinutes` makes typing it twice impossible, so a corrected
part allowance cannot leave a stale header behind. `timeLimitMinutes` is **not** in the pinned
name list, so no downstream gate is affected — but plan 09 must call `readingSetMinutes(set)`
where the listening source reads `set.timeLimitMinutes`.

**Persistence — the six lockstep sites, for the third time.** `readingAttempts:
Record<string, CelpipReadingAttempt[]>` through `CelpipProgressState`, `CELPIP_EMPTY`,
`celpipProgressSchema`, `MERGE_CELPIP_EMPTY`, `celpipCoerce` and `mergeCelpip`. The merge rule
is one line — the same `unionRecord(x.f, y.f, (p, q) => canonical([...p, ...q]))` the other
three fields use — so it inherits their proof rather than needing a new one.

```ts
export interface CelpipReadingAttempt {
  setId: string; date: string;          // the natural key, joined on a NUL
  durationSeconds: number;
  answers: Record<string, number>;      // question id OR BLANK id -> chosen option index
  correct: number; total: number;
  outOfTime: boolean;                   // latched if ANY part's clock ran out
}
```

`taskType` was **not** widened, and nothing in `celpipReadingEntry` mirrors a list of set ids
or part kinds. A set cut from the phase for the calendar must never delete a result the
learner already has.

**In-progress answers are not persisted, and both halves of the contract say so out loud.**
The runner's working sheet lives in React state and dies with the set. Persisting it would
create a map with a real delete site — it *has* to clear on submit, or a finished attempt
pre-fills the next timed run — riding the one `updatedAt` this state carries, which
`pickDraftsSide` already rides; a device stamping while saving an in-progress answer would
then also win the `drafts` map and resurrect a cleared writing draft (the `fca41b7` defect).
The reasoning is recorded in a comment on the attempt type, in a comment on
`addReadingAttempt`, and — more usefully — in an assertion in **each** script that a client
sending `inProgress`, `partIndex` or `notes` has all three stripped.

**Answer indexes are dropped, never clamped,** and the merge reuses `indexRecord` rather than
copying it: the reading sheet has a *wider key space* than the listening one (blanks live in
it too) carrying the same values, and the drop-never-clamp rule must not fork between them.

**Fixtures, not one-off assertions.** Five new states went into `celpipStates` —
`readingOnly`, `allFourSkills`, `readingTwins`, `readingBlankOnly` and `legacyNoReadingField`
— so the O(n³) sweep exercises each against every other under both bracketings. That single
edit is most of the jump from **12,040 to 20,146** assertions. `legacyNoReadingField` is the
row shape sitting in Postgres *right now*: written between plan 04 and this one, so writing,
speaking and listening present and `readingAttempts` **absent** rather than empty.

### Task 2 — the drop-down blank, the runner, and its route (commit `047a42b`)

**`src/components/celpip/DropdownBlank.tsx`** is one blank rendered inline in prose: a native
`select` carrying the blank's options, `aria-label`ed with which blank it is, an empty first
option so an untouched blank reads as untouched, disabled after submit, and taking the same
teal-for-correct / vermilion-for-wrong `color-mix` fills and check/cross icons the shipped
practice room's option buttons take.

A **native select and not a custom listbox**, for three reasons that all point the same way:
it is keyboard- and screen-reader-correct for free, it opens as the system picker on a phone,
and the exam itself uses a drop-down — so this trains the control she will actually meet. It
is also why this section needed no combobox library, which is what keeps T-02.1-SC honest.

After submit the component renders the correct option **and the explanation, beneath the
blank it belongs to** rather than in a list at the foot of the text. That placement is the
point: the reason an option was wrong is only legible next to the sentence that supplies the
context.

**`src/components/celpip/ReadingRunner.tsx`** is the Writing simulator's state machine —
`phase`/`mode`/`startedAt`/`expired`/`locked`/`finalizedRef` — with the sticky-header `Timer`
reused unchanged and the two-way expiry exit on screen. Four things in it are worth recording:

- **The clock is armed per part, and the `Timer` is KEYED by `part.id`.** The plan said to rely
  on `Timer`'s reset-on-changed-`totalSeconds` behaviour. That is not sufficient and the exam
  itself is the counterexample: correspondence and viewpoints are **both 11 minutes**, so two
  parts sharing an allowance would carry the previous part's remaining seconds forward. It
  happens not to bite in the exam's 11/8/9/11 order, but plan 09 or 10 may author a partial
  set. Remounting cannot be got wrong by an author. See Deviations.
- **One answers map, one filter.** `partItems()` flattens blanks and questions into a common
  `GradedItem`, and scoring is
  `items.filter((item) => answers[item.id] === item.answer).length` — the same shape
  `ReadingRoom` uses. Per D-02 no AI is involved; an answer key is not automated scoring.
- **Submission is never gated on completeness** — the one deliberate divergence from
  `ReadingRoom`, which disables its submit until every question is answered. Under exam
  conditions a blank is a real outcome, and the house rule is never to block on a quality
  signal. Empty items score as wrong and the copy says so, twice.
- **Expiry never discards.** A part running out locks input and offers three ways on: go to
  the next part, continue this one untimed, or submit the whole set as-is. `outOfTime` latches
  for the attempt. `finalizeAttempt` carries the once-only guard and is wired to both exits
  from the results view, with the ref reset on retry.

**The route** mirrors the writing route: non-async `generateStaticParams` over `READING_SETS`
(empty today, and that is fine), an async page whose `params` is a Promise that is awaited,
`notFound()` **called** rather than returned, no `"use client"`, and the `JsonLd`
LearningResource envelope with `teaches: "CELPIP Reading"`. Next 16's bundled docs for
`generateStaticParams` and `notFound` were read before writing it, per AGENTS.md.

**The set is resolved on the client from an id.** Plan 05 measured a resolved set crossing the
server/client boundary being inlined into the served HTML — 41 of 42 authored strings. For a
reading set that would be the answer key *and* ~2,500 words of passage in `View source`. The
route passes `set.id`; `ReadingRunner` calls `getReadingSet`.

## Mutation testing — 26 mutations, and the harness bug that faked a clean sweep

A first green is not evidence. **26 mutations: 24 caught, 2 survived** (plus 2 controls that
correctly survived). The harness aborts loudly on a missing OR ambiguous anchor, backs the
target up to an explicit path, and restores in a `finally`. Both guards fired for real.

### The harness was wrong first, and the CONTROLS are what found it

The first full run reported **18 of 18 caught** — including two deliberately harmless control
edits (a reworded button label, a reworded sentence of brief copy). A gate that fails on
harmless edits is a gate the next person disables rather than fixes, so that result was the
alarm.

Cause: `child_process.execSync` falls back to **`cmd.exe`** on Windows, where single quotes
are not quote characters at all. The plan's own gate contains an `awk` program in single
quotes, so `awk` received several broken arguments, exited non-zero, and **every** mutation
read as "caught" whatever the code said. Re-run with `shell` pinned to bash, the controls
survive and one real survivor appears. Recorded because a mutation report is only worth
anything if the mutations in it actually ran.

### The CRLF hazard fired for real

Four schema mutations aborted with `anchor NOT FOUND`. Cause: **`progress-schema.ts` is
entirely CRLF (754 of 754 line endings) while `progress-merge.ts` and the components are
LF.** A `\n`-anchored replacement matches nothing in half this repo's files and would have
silently "survived" under a harness without the guard. The harness now tries the anchor as
written, then as CRLF, and aborts if neither lands exactly once.

The ambiguity guard also fired twice, correctly: `readingKey`/`listeningKey` and the guard
clauses of `celpipReadingEntry`/`celpipListeningEntry` are byte-identical between the two
skills, so a body-only anchor would have hit the wrong function. Re-anchored on the function
signatures.

### Caught (24)

**Merge (10):** reading merged by object spread instead of the union rule · `readingAttempts`
dropped from `MERGE_CELPIP_EMPTY` · the reading coercer bypassed and the raw map spread
through · the natural key reduced to `setId` (two sittings of one set collapsing to one) · an
identity-less entry kept rather than dropped · an out-of-range index **clamped** rather than
dropped · the answer sheet spread raw so poisoned item ids reach the stored shape · a negative

**Schema (5):** `readingAttempts` dropped from the write schema (the silent

**Components (3):** a completeness gate added to the submit button — the ReadingRoom rule this
plan diverges from · a passage rendered as raw HTML for formatting convenience · the blank's

**Controls (2), which correctly did NOT fail:** a relabelled button and a reworded sentence.

**Strengthened finalize gate (2), added after the survivor below:** the once-only guard

## Deviations from Plan

### [Rule 1 — latent bug in the plan's own instruction] The per-part Timer is keyed, not merely re-fed

The plan says to "use `Timer`'s documented reset-on-changed-`totalSeconds` behaviour to
re-arm as the learner moves from part to part". `Timer` resets on a **changed**
`totalSeconds`; two adjacent parts sharing an allowance therefore do **not** re-arm it, and
the exam's own format is the counterexample — **correspondence and viewpoints are both 11
minutes**. In the 11/8/9/11 order every adjacent pair happens to differ, so the defect does
not bite today; it bites the first time a partial or reordered set is authored, which plans 09
and 10 may well do.

- **Fix:** `key={part.id}` on the `Timer`, alongside the part's `totalSeconds`. Remounting is
  not defeatable by an author, where a value-change contract is.
- **Files:** `src/components/celpip/ReadingRunner.tsx` · **Commit:** `047a42b`

### [Rule 2 — the gate could not catch its own defect] The `finalizedRef` gate was strengthened

Task 2's gate is `grep -c "finalizedRef" … >= 3`. **Mutation testing shows it does not work:**
deleting the two guard lines from `finalizeAttempt` leaves three occurrences (the declaration
and the two resets in `retry`), so the count still passes while the attempt is recorded twice
— exactly the Phase 1 defect the guard exists for.

The plan's gate was run **unmodified** and passes (5). It is kept, and a conjunction added
around it:

```bash
grep -c "finalizedRef" src/components/celpip/ReadingRunner.tsx | awk '{ exit ($1 >= 3) ? 0 : 1 }'
[ "$(grep -c 'if (finalizedRef.current) return;' F)" = "1" ]   # the guard itself
[ "$(grep -c 'finalizedRef.current = true;'      F)" = "1" ]
[ "$(grep -c 'onClick={finalizeAttempt}'         F)" = "1" ]   # every exit path is wired
```

All four pass on the pristine tree, and both mutations that slipped past the count-only gate
now fail. This is 02.1-04's `onboundary` lesson in the same direction: a single-token gate is
a presence check, not a behaviour check.

### [Judgement call — diverging from 02.1-04's precedent] The raw-HTML gate was kept literally intact

The plan's gate greps `src/components/celpip` for the raw-HTML prop and requires **zero**
matches. My first draft of `ReadingRunner` documented the prohibition by name, which made the
gate fail on **its own documentation** — the mirror of the situation 02.1-04 hit with
`onboundary`, where the gate was tightened to exclude comment lines.

I did **not** tighten it here, and the difference is deliberate. Plan 04's comment had to name
`onboundary` because it explains a specific browser bug a contributor needs to look up. This
prohibition loses nothing by not naming the identifier: the comment says formatting is
expressed as structure, names the exact temptation it exists to stop (a bold run or a line
break inside a passage), and points at T-02.1-36. Keeping the gate as a blunt,
directory-wide, zero-match check is worth more to plans 09–12 than the token appearing in
prose — a tightened gate has an exclusion regex that can itself be wrong.

**Handoff consequence, and it is a landmine if unrecorded:** the gate is **token-literal over
the whole directory**, so no comment in `src/components/celpip` may name that prop either. The
comment in `ReadingRunner` says so in as many words.

### [Rule 1 — defect in my own first draft] A raw NUL byte reached `progress-merge.ts`

Writing `\u0000` through an edit produced a **raw NUL byte** in `readingKey` rather than the
two-character escape — precisely the hazard 02.1-04 recorded. Left alone it would have made
the file binary to git again and this plan's 63-line diff to it unreviewable. Converted by
script (the only way that works); the file now has **zero** raw NUL bytes and `git diff
--stat` renders it as text. Identical at runtime — the natural-key and de-duplication
assertions all pass.

### [Judgement call] `readingAttemptsForSet` added alongside `addReadingAttempt`

The plan names only `addReadingAttempt`. The other three skills all have both, plan 09 will
want per-set history on the landing, and adding the twin now keeps the store symmetric across
four skills. Four lines.

### [Judgement call] `verify-celpip-content.mts` was NOT touched

Plan 03's handoff names later plans as its append targets. This plan authors **no content** —
`READING_SETS` is empty — so a reading group would be vacuous today and would assert against a

### [Observation] `scripts/verify-schema.mts` still contains one raw NUL byte

## Known Stubs

**`READING_SETS` is empty, on purpose, and the landing says so by itself.** That is the
designed intermediate state, not an unfinished edge: `section()` derives availability from
bank contents, so `/celpip` reports Reading as "Not yet available" until plan 09 replaces
`const READING_SOURCE = undefined` and fills the bank. Plan 02 proved by control mutation that
a bank which exists but is empty still reports unavailable.

**`ReadingRunner` and `DropdownBlank` are reachable by no URL today.** `/celpip/reading/{id}`
404s for every id because the bank is empty, which is also why no browser check of either was
possible.

**Id uniqueness across questions and blanks is documented but not gated.** The constraint is
real — a collision silently overwrites one of two answers and mis-scores the sheet — and this
plan cannot gate it, because gating it needs a bank to gate. Plan 09 owns it. Named in the
handoff and in the ledger.

No other stub. The types, the persistence field, the control, the runner and the route are
complete — nothing in them is a placeholder waiting to be filled in.
