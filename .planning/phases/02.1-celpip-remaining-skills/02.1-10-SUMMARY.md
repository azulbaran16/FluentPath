The stimulus is a five-row programme table with column headers and **four exception notes**, and
the exceptions are the part rather than decoration:

| The note | What it makes askable |
|---|---|
| Visitors from outside the township add $15 to any ten-week fee | A blank that cannot be answered from the table alone — $145 becomes $160 |
| The centre closes on statutory holidays; the 16 February class is made up on 23 March | A blank whose tempting alternative contradicts the note's own first sentence |
| A place booked online is held for forty-eight hours, then released | A blank where every wrong option is a longer, more comfortable reading of a deliberately tight rule |
| Nobody under sixteen may use the weight room without the orientation | A question testing whether she reads a *condition* as an *age bar* |

The three closing questions are inference and not lookup: which programme suits somebody free
only after six on a weekday and away at weekends (two constraints held at once, each wrong option
failing exactly one); what a family of five pays when the column says "$40 **per family**" (the
three wrong answers are the three ways of not reading those last two words); and the age-rule
question above.

Every blank's tempting wrong option is a neighbouring row's fact or a superseded note. None is
ungrammatical — that is the rule the file header states, and the reason this question type is
worth authoring at all.

### Task 2 — the viewpoints part, and the set closes (commit `c137ae4`)

**`rs1-viewpoints` — 11 minutes, ten items: five questions on the article, then five blanks in
the reader comment.** A **532-word** original article on an invented town's fare-free bus trial,
four named people, and a **159-word** comment beneath it.

**The part tests attribution, and four of the five questions require it** — who doubts the
number, which two agree the trial worked and disagree on what follows, whose case rests on *who*
rides rather than how many, and which of them would take a fare back if it bought later buses.
The fifth is the whole-article judgement: what all four accept.

**The positions overlap on purpose,** because four people disagreeing about everything is both
easier and less like the real thing:

- Prewitt and Bouchard-Ng want the same outcome for different reasons.
- Prewitt and Sarrazin agree the trial worked and split on what follows.
- Sarrazin and Trang both end up pointing at service, from opposite premises.

Every question is settled by a **named sentence**, and each explanation says which. An
attribution question answerable from tone rather than from a sentence is a guess dressed as an
item.

The comment's blanks are where stance and attribution meet: each wrong option is grammatical and
fails on exactly one of two things — it credits the wrong person, or it reverses a stance the
writer took two lines earlier. One is ruled out by the article's closing fact (the grant *ends*
in June; it is not renewed then), which is the same move the correspondence blanks make with the
head count.

**The first attempt at the active control reported a clean 0 and was a lie**, and it is written
down because the way it was caught generalises. Two faults compounded:

1. The injected prop was named `leakedSet`, which the harness's `\bset=\{` regex does not match —
   so the injection was not the defect the gate defends against, and the harness passed.
2. `next start` on the same port **failed with `EADDRINUSE` and the old server kept answering**.
   The measurement was taken against the previous build.

The tell was that the byte count came back **identical to the digit** — 36,932 both times. A
passive control cannot catch this, because the set title is in the document in both builds. Only
the byte count and the harness's own silence gave it away. Re-injected with the real prop name
(`set={set}`) on a fresh port, the harness **fails** (`FAIL the reading route never hands the
runner a resolved set`) and the probe finds 125 of 149 authored strings — the table, the article,
the comment, the stems, the options and the explanations — readable in `view-source`. Reverted
with `git checkout --`, rebuilt, re-measured on a third port: back to zero, with no trace of the
injection in either file.

Stated rather than implied, as plans 05 and 09 stated it: the bank **is** present in exactly one
`.next/static/chunks/*.js` file. That is the posture T-02.1-41 accepts, and the served HTML

## Deviations from Plan

### [Rule 1 — a defect in shipped content that this plan would have doubled] The answer was the first option in ten of fifteen drop-down blanks

Measured before anything was changed:

```
rs1-correspondence  blanks: 0 0 0 0 0
rs1-diagram         blanks: 0 0 0 0 0     <- authored by this plan
rs1-viewpoints      blanks: 2 0 1 3 1
```

Options render in declared order, so a learner practising against that bank learns, without ever
being told, that **the answer is the top of the list**. She then sits an exam that randomises,
having trained a cue it does not supply. It is the same failure as an ungrammatical distractor —
teaching her to answer the hardest question type the wrong way — and this file's own header
already warns about that failure in its other form. It is invisible to every assertion that
looks at one item at a time, which is why 519 of them passed over it.

The diagram half was mine. **The correspondence half was plan 09's**, and it is fixed here rather
than reported, because a half-fix leaves part 1 — the first thing she meets — still uniform, and
because this plan was about to add ten more blanks to the same sitting.

- **Fix:** options redistributed across all four positions in both parts, **content unchanged**.
  Final spread: correspondence `2 3 1 0 2`, diagram `3 1 0 2 1`, viewpoints `2 0 1 3 1`. The
  diagram's three questions (`0 0 0` as authored) became `1 2 0`.
- **And a second-order fix the first one forced:** five explanations said "the second option",
  "the fourth", "the last one". Re-ordering makes prose like that **silently false**.
  Explanations now name an option by its content — "saying he cannot manage it", "the hundred and
  thirty", "leaving it open" — which also reads better beside a `select` whose order she cannot

- **Gate:** a part whose questions or blanks all key to one index now fails, where the part has

### [Rule 1 — a latent defect in shipped code that this plan's content made visible] Each part now runs its items in the exam's own order

`ReadingRunner` rendered `passage → diagram → blankText → questions` for **every** part. That is
correct for the diagram part and wrong for the other two that carry blanks.

The exam runs correspondence as six questions about the email and *then* the reply with its five
blanks, and viewpoints as five questions about the article and *then* the reader comment with its
five. The runner was handing her the reply **before** the questions about the email above it.
Plan 09's own file comment says "the six-then-five order is not interchangeable… she should meet
the blanks in the position she will meet them on the day" — and the code did the opposite, with
nothing anywhere disagreeing: the items are all present and all gradable either way, so `tsc`,
lint, the build and all 519 assertions passed. What changes is what she has read before she
answers, which makes the part easier than the one she will sit.

This is not merely inherited. The plan requires the viewpoints part to run **five questions then
five blanks**, and shipping content whose documented order the renderer contradicts would have
made this summary false on the day it was written.

- **Fix:** `readingPartBlanksFirst(kind)` in `celpip.ts` — a total `Record` over the four kinds,
  so a fifth fails `tsc` rather than silently inheriting an order nobody chose. Only `diagram` is
  `true`. Both the live view and the post-submit review consult it.
- **Gate, as a conjunction rather than a token count** — plan 08's `finalizedRef` lesson: the
  harness pins the table against `READING_PART_SHAPE.blanksFirst`, requires exactly four guard
  sites, **and** requires that no `{part.blankText && …}` renders outside a guard. The count
  alone would pass if a call site were deleted and its `BlankTextView` left unconditional; the
  unguarded-render check alone would pass if the guard were present but always true.
- **Files:** `src/lib/celpip.ts`, `src/components/celpip/ReadingRunner.tsx`,
  `scripts/verify-celpip-content.mts` · **Commit:** `29d0444`

### [Rule 2 — gates the plan did not list, all silent when broken] Four more assertions on the two new parts

- **A part carries exactly the stimuli its kind carries**, asserted per kind rather than as "at
  least one". A diagram part authored with a passage renders **no table**, and its five blanks —
  answerable only from rows and notes — become unanswerable while every other assertion passes.
- **No two diagram rows share a label.** Each row is a `<tr key={row.label}>`, so a duplicate is
  a React key collision; worse for the learner, it makes any item turning on "which row"
  ambiguous with nothing on the page saying which was meant.
- **The column headers cover the row-label column and every cell**, and every row has the same
  number of cells. The row label renders as its own `<th scope="row">`, so a tabular diagram
  needs **one more header than a row has cells**. Get it wrong and every `<th scope="col">` is
  announced against the wrong cell — silently, to the one user who cannot see the misalignment.
- **Every cell, header and note is non-empty.**
