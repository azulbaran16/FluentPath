<objective>
Close the CELPIP loop: a route that validates and merges on write, a store hoisted to one instance with server sync through the shared queue, and a reconcile that runs once per authenticated load — so the beta user's attempt history stops living only in her browser.

Purpose: D-04 put this domain in scope because the first beta user has a real exam date and her attempt history is live data, not test data. D-05 keeps it in its own column and its own request so a twenty-XP tick never re-uploads an essay.
Output: `src/app/api/celpip-progress/route.ts`, a module-store `src/lib/celpip-progress.ts` with sync, and the CELPIP reconcile wired into the single app-wide mount.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated browser → `PUT /api/celpip-progress` | Learner-authored essay prose crosses into persistent storage |
| stored CELPIP blob → app | Free-form text of unknown integrity is read on every authenticated load |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-26 | Information Disclosure | CELPIP route access control | high | mitigate | No identifier is accepted from the client; `session.user.id` is the sole key on the select and the update, matching the progress route's IDOR-safe shape |
| T-02-27 | Denial of Service | Essay-bearing payload size | high | mitigate | Body length is checked before parsing and refused with 413; per-entry text length is already bounded by the schema from 02-05; the per-account rate limiter applies here too |
| T-02-28 | Tampering | Replayed CELPIP snapshot | medium | mitigate | Merge-on-write plus the queue's sequence compare-and-clear make replay and duplicate delivery no-ops |
| T-02-29 | Tampering | Draft resurrection pre-filling a timed attempt | high | mitigate | The whole-map draft rule from 02-05 is exercised end to end here on the D-01b instant, stamped by `clearDraft` through the single persist funnel so the clearing device always outranks the stale one; the empty-editor case is verified by hand in this task and again at the phase gate |
| T-02-30 | Denial of Service | Essay re-upload on every keystroke | medium | mitigate | A separate queue slot per domain plus a longer debounce on the CELPIP write; the progress payload never carries essay text |
