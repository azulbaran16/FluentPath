<objective>
Give the CELPIP attempt store a home in Postgres and a merge that cannot resurrect a cleared draft: one additive nullable column (D-05), a zod contract and a de-duplicating attempt merge — all verified before anything touches a database.

Purpose: D-04 pulled the Phase 1 CELPIP store into this phase because the first beta user is practising for a real exam date and would lose her attempt history on a device change or a browser cleanup. Her history exists today only in her browser. D-01a also singles drafts out: a key union there would resurrect a cleared draft and re-introduce exactly the defect Phase 1 found and fixed in `fca41b7`, where a submitted answer pre-filled the next timed attempt.
Output: `User.celpipProgress`, the CELPIP half of the shared contract module, `mergeCelpip`, and extended verification scripts.
</objective>

  <behavior>
    - Attempt arrays for the same task from two devices are combined, entries occurring on both sides appear once, and the result is sorted ascending by submission timestamp so merging twice yields an identical array.
    - Merging a snapshot with itself returns an equal value — without the sort, array identity would differ on each pass and the per-load reconcile would write on every page view.
    - The drafts map is taken whole from the side with the later D-01b instant; a draft cleared on that side stays cleared, including when both sides carry the same calendar day and even though the clearing side holds the smaller map. No key union anywhere near drafts.
    - A side carrying an instant beats a side carrying none, so a Phase 1 blob that has not been touched since never overrides a device that has just cleared a draft.
    - When neither side carries an instant, the tie is broken on values only and totally — never on which side came from the network, and never in a way that leaves two equally-ranked maps.
    - The merged instant is the later of the two and is never freshly generated, so merging changes nothing about how recent the state claims to be.
    - `mergeCelpip` is total: null, undefined, non-object and garbage on either side produce a well-formed state and never throw.
  </behavior>
  <action>
    Add `mergeCelpip(a, b)` and `celpipEqual(a, b)` to `src/lib/progress-merge.ts`, reusing the generic primitives rather than inventing a second set. The two domain states share no field shapes, so keep two thin domain merges over one set of shared primitives instead of a single general-purpose object merger, which would have to encode per-field policy anyway and would bury the carve-outs.

    Merge `attempts` by key union, and per key concatenate the two arrays, de-duplicate on the natural key formed from the task id and the attempt's submission timestamp — the attempt record has no id, and that timestamp is an ISO instant, so a collision needs two submissions in the same millisecond — then sort ascending by that timestamp. State in a comment that the sort is a correctness requirement, not cosmetics: without a canonical order the merge is not idempotent, and under the per-load reconcile that produces a write on every page load.

    Merge `drafts` as a whole map taken from the side with the later D-01b instant, exactly as D-01a specifies as amended by D-01b, with no key union. Merge the instant itself with the `laterInstant` helper from 02-01, so the merged state carries the later of the two and never a freshly generated one — a stamp here would make every merged copy outrank every unmerged one. A side holding an instant outranks a side holding none. Only when neither side has one does the tie fall to values, and that tie-break has to be a *total* order or the merge stops being commutative: prefer the map with more keys, then the greater canonical serialization of the map with its keys sorted. Do not stop at comparing key lists — drafts hold learner text, so two maps can share every key and still differ, and a rule that ranks them equal lets the two sides keep picking their own copy forever. Keep the whole function total, falling back for an unreadable side to a module-local CELPIP empty literal declared in this file for the same reason the progress one was: the merge module stays free of runtime relative imports so it loads standalone under node. | Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-21 | Tampering | `prisma/schema.prisma` edit applied at container start | critical | mitigate | The read-only diff is taken against a pinned pre-phase baseline commit, asserted to be exactly one additive column statement with nothing destructive, before the change can reach any database; the pin is asserted to be an ancestor that does not already contain the column, the Dockerfile is asserted unchanged, and the phase runs on a branch so nothing deploys until it is verified |
