<objective>
Give the CELPIP attempt store a home in Postgres and a merge that cannot resurrect a cleared draft: one additive nullable column (D-05), a zod contract and a de-duplicating attempt merge — all verified before anything touches a database.

Purpose: D-04 pulled the Phase 1 CELPIP store into this phase because the first beta user is practising for a real exam date and would lose her attempt history on a device change or a browser cleanup. Her history exists today only in her browser. Output: `User.celpipProgress`, the CELPIP half of the shared contract module, `mergeCelpip`, and extended verification scripts.
</objective>

    - The drafts map is taken whole from the side with the later activity marker; a draft cleared on the newer side stays cleared. No key union anywhere near drafts.
    - When both sides have the same activity marker or none at all, the tie is broken on values only — never on which side came from the network.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-21 | Tampering | `prisma/schema.prisma` edit applied at container start | critical | mitigate | The read-only diff is generated and asserted to be exactly one additive column statement with nothing destructive, before the change can reach any database; the Dockerfile is asserted unchanged |
| T-02-22 | Tampering | CELPIP draft merge | high | mitigate | Whole-field selection by activity marker, never key union, so a cleared draft cannot pre-fill the next timed attempt — the Phase 1 defect stays fixed |
| T-02-23 | Denial of Service | Unbounded essay text in the CELPIP blob | medium | mitigate | Explicit maximum lengths on attempt text and draft text in the schema, with over-length entries dropped rather than stored |
