<objective>
Gate the phase on evidence. First prove against the live database that no learner's stored progress is damaged by the new contract, then run the full automated suite, then have a human confirm the four ROADMAP success criteria that no build step can prove.

Purpose: research flagged one assumption as high risk and explicitly refused to treat it as a finding — that every existing row in production `User.progress` parses cleanly under the new schema. If one does not, the safe-default read path would quietly zero a real learner's progress. This is a live database with an active beta user practising for a dated exam, so that assumption gets checked before anything ships, not after.
Output: an audit report over live data, a green full suite, a corrected project instruction file, and a human sign-off or a concrete defect list.
</objective>

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 3: Human verification — the four Phase 2 success criteria</name>
  <what-built>Server-side progress. Postgres is now the authoritative copy for both the learning progress store and the CELPIP attempt store, each in its own column and its own endpoint. Both stores are single module-level instances behind useSyncExternalStore, reconciled once per authenticated load with a field-by-field merge that runs identically on client and server, so a write can be replayed or duplicated without regressing anything. Every write goes through a localStorage queue that survives a tab close, retries on full-jitter backoff, flushes on reconnect and at page-hide, and surfaces a discreet not-synced indicator only after failure has genuinely persisted. Payloads are validated with a shared zod contract that strips unknown fields and saves the rest, and corrupt stored data — in Postgres or localStorage — loads as the empty state.</what-built>
  <how-to-verify>
    Prerequisites: Docker Desktop running, `docker compose up -d db`, local DATABASE_URL pointing at the local Postgres, `npx prisma db push`, then `npm run dev`. Keep `npm run db:studio` open in a second terminal.

    1. Cross-device identity (criterion 1). Sign in, complete a scenario, add a vocabulary card and answer a grammar question wrong then right. Note the completions, XP, streak, CEFR level and due-review count on /dashboard. Open a **fresh browser profile or incognito window** — not just a new tab, localStorage must be empty — sign in as the same learner, and confirm all five figures match. Cross-check the row in Prisma Studio.
    2. Anonymous progress survives signup (criterion 2). In a fresh profile, signed out, complete two scenarios and confirm the local key holds them in DevTools. Sign in to an account that **already has different progress**. Confirm the account now holds the union: both the anonymous completions and the pre-existing ones. This is the half a server-wins implementation would silently pass, so check both directions.
    3. CELPIP history and the blank editor. Signed out, complete a CELPIP writing task. Sign in and confirm the attempt appears in the account's history and in the celpipProgress column. Then reopen that same task and confirm the editor is **blank** — a submitted answer must never pre-fill the next timed attempt.
    4. Malformed write and corrupt stored data (criterion 3). With the dev server running and a valid session cookie, PUT a non-object body to /api/progress and confirm a 400; re-read the row in Studio and confirm it is untouched. Then PUT a body with one unknown extra field and a bad value for xp, and confirm it succeeds with the unknown field absent and the rest saved. Finally, in Studio, set that user's progress to a deliberately broken JSON string, load /dashboard, and confirm the empty state renders rather than a 500.
    5. Offline write reaches the server (criterion 4). Open DevTools, set the network to Offline, complete a scenario, and confirm the queue slot exists in localStorage. **Close the tab entirely.** Reopen it online, and confirm the write lands in Studio and the queue slot clears. Separately, keep the network offline long enough for three retries and confirm the discreet not-synced indicator appears, then restore the network and confirm it disappears on the next success.
    6. No noise on the happy path. With the network healthy, reload /review and confirm the Network tab shows **one** GET to /api/progress, not four. Reload /dashboard several times with no learner activity and confirm the User row's updatedAt does not advance — the reconcile must not write when the merge changed nothing.
    7. Anonymous learners see no indicator. Signed out, open /celpip and confirm no sync indicator appears anywhere.
    8. Audit sign-off. Confirm the Task 1 audit reported every production row clean, and that you are satisfied the beta user's data is safe before this is pushed.
