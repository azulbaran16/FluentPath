<objective>
The tracer. One native scenario is carried the whole way — bank, derived coverage, spaced-repetition
ids, renderer, advertised session length, gate — so that the four scenarios after it are authoring
against a machine that has already been proved rather than one that is being invented under them.

`native/phrasal-verbs` is the tracer because it is the only scenario in the world that touches three
Class-A banks (phrases, vocabulary, grammar), and because research names it the best-specified of
the five: the pedagogical unit is verb + particle + sense, which is a criterion an author can apply
item by item rather than a matter of taste.

Depth creates the session-length problem in the same change that creates the depth, so this plan
solves it in the same change. It also lands the two gates research listed as Wave-0 gaps — the
payload ceiling and a deck-length claim — plus one this phase's own D-04 makes non-optional: a
committed way to detect an id being re-pointed onto different content.

**If execution stops right after this plan**, the learner has one genuinely deep native scenario
(18 phrases, 42 cards, batched, honestly timed), and every plan after it inherits a gate that makes
a silent re-point impossible. Nothing anywhere claims depth that is not written: coverage is
derived, so the other four scenarios simply continue to report their floors.

Purpose: prove the whole machine on one scenario before 100+ items exist.
Output: a deepened recall pair, a batched deck, and three new committed gates.
</objective>

- an empty input yields no batches;
- an input at or below the ceiling yields exactly one batch holding the whole input, so every deck

across the whole sitting, a control to carry on, and the fact that stopping here is fine and
everything rated is already scheduled. When the last batch ends, the existing completion screen
shows, with its totals counted across the whole sitting rather than the final batch. Restarting
returns to the first card of the first batch. Nothing else about the component changes: every rating
still goes through `recordAttempt` and nothing else, and no new progress field is written.

This is a batching change and not a redesign — D-03 says so in as many words.

3. *The saturated payload stays under the cap.* Reproduce 03-11's construction as a committed

   `reviewableIds()` can emit plus every other field at a maximum, serialise it the way the sync

**B. A new gate: `scripts/verify-id-stability.mts`**, plus its committed fixture
`scripts/fixtures/scheduled-item-ids.json`.

This is the one thing AGENTS.md says has no detection today: an id whose content is re-pointed
silently transfers a learner's box and due date onto material she has never seen, with no migration
path and no way to find out afterwards. This phase deletes and replaces items on purpose (D-04), so
it needs the detector before it does that.

Scope it to the scheduled kinds — phrase, vocab and grammar — because those are the only ids a
Postgres `srs` entry is ever keyed by. The fixture maps each scheduled composed id to a hash of the
authored content behind it. The script asserts three rules and nothing more:

- an id present in both the fixture and the tree must hash the same — re-pointing fails;
- an id in the tree and not in the fixture is an addition and is always fine;
- an id in the fixture and not in the tree must appear in the fixture's own list of deliberately
  retired ids, each with a reason, so a deletion is auditable rather than merely survivable;
- an id on that retired list must NOT be emitted by the banks — a retirement is final, and an id
  coming back is the same as a re-point wearing a different hat.

That last rule is what later plans lean on: a plan that retires items proves the retirement held by
running this gate, rather than by grepping source, where a comment or a near-miss substring would
make the check lie in either direction.

Give it an update mode that regenerates the fixture, and say in the header that the regenerated diff
IS the review: a re-point shows up as a changed hash on an unchanged id, which is exactly the thing
a reader should refuse. Same posture as every other script here — no runner, no dependency, `.mts`,
explicit `.ts` extensions, verdict is the exit code.

Seed the fixture from the tree as it stands after Task 2. Tasks 1 and 2 were pure additions and
their own diffs prove it, so the window this gate protects opens here, which is the plan that
introduces it and the point after which the risky work starts.
